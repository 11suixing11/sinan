# sing-box 业务页面的读取与编辑保护

业务页面可以在刷新失败时保留上次成功读取的数据，供管理员查看；上次数据不能继续作为当前编辑依据。此规则限制界面操作，后端仍负责管理员身份、资源存在、链路身份、授权并集及套餐分配的当前业务校验，不把界面问题称为权限绕过。

`useResource` 保留原 `loading` 和历史数据语义，另外提供 `refreshing` 与 `fresh`。只有相同路径已有非 null 数据（空数组合法）、最后读取成功且当前没有进行中的读取时，`fresh` 才为真。显式重读立即关闭编辑，后台轮询开始时同样关闭；失败后保持关闭，下一次成功读取后才恢复。

| 操作 | 所需的当前读取 |
| --- | --- |
| 创建、编辑或删除策略组 | 策略组、节点、链路 |
| 创建、编辑或删除套餐模板 | 套餐模板 |
| 创建、编辑、删除代理用户或重置订阅令牌 | 代理用户 |
| 单独节点授权与撤销 | 代理用户、节点、链路、当前用户授权 |
| 给用户分配策略组 | 当前用户、策略组、已分配策略组 |
| 给用户分配套餐 | 当前用户、套餐模板、当前套餐资格 |

流量图表请求不参与授权或套餐写入条件。其读取失败保留图表错误说明，不阻塞无关业务操作。

已经打开的编辑与确认窗口遵循相同条件：字段及提交暂时关闭，输入和选择保留，取消、关闭和重试仍可用。表单提交处理器也检查条件，不能只依靠按钮样式。读取期间不会显示为正在保存或正在删除。

策略组节点及链路选择使用受控草稿。已经不可用的链路不会在打开窗口时被过滤掉；恢复读取后消失或改变身份的选择也保留并标注，管理员明确取消后才能保存。用户策略分配的未保存草稿不会被显式重读覆盖。套餐选择消失时保留所选 ID 并要求重新选择。编辑或删除的实体在成功重读后已经不存在时，窗口继续禁止提交并说明原因。

这些条件不增加资源 revision、乐观并发锁或新的业务 API，也不保证读取完成后到写入之间数据永不变化。写入仍由服务端事务校验。套餐分配请求 ID、已分配套餐快照、节点凭据、策略与单独授权的并集以及计量账本规则保持。

回归代码位于 `web/tests/singbox-entitlement-draft.mjs`：使用实际构建产物和专属回环 API 夹具，覆盖桌面与手机、真实轮询、GET 失败、恢复请求未完成、恢复成功、窗口草稿保留、显式取消失效资源及用量请求与授权操作的独立性。统一冻结后的 1280/390 专项已通过；五次夹具失败及对应修复保留在[整步验收记录](acceptance/debian-inputs-and-singbox-snapshots.md)中。该结果认证界面保护，不替代真实生产 API 或持续代理负载验收。
