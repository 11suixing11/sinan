这是用户要求“继续下一步”后的第三个大步骤：重新排版管理界面，并处理[全仓缺陷扫描](defect-scan-20261003.md)中的 D12–D16。工作在集成分支 `claude/sinan-scan-refactor-odrgr3` 上进行，起点是第二步的提交 `429f42e`。设计决定见 [ADR 0084](../adr/0084-admin-layout-and-node-sections.md)。

## 修改内容

- **外框与导航：**
  - 导航按任务分为五组：概览、服务器、代理服务、扩展插件、系统。
  - 面包屑显示“分组 / 页面”。
  - 宽度不超过 800 像素时，导航收进“菜单”按钮，退出登录始终可见。
  - 外框样式从压缩的 `styles.css` 拆到可读的 `app/shell.css`。
  - 对话框通过 portal 渲染到文档根节点，标题使用唯一 ID。
- **代理节点页（D13 及 D17 的界面部分）：**
  - 页面分为“节点库”“链路”“订阅来源”三个分区，由 `view` 参数选择；旧的 `kind=chains` 及 `/plugins/sing-box/chains` 仍打开链路分区。
  - 六个读取改为同一轮请求，有变化的数据整轮一起发布；内容不变的成员先恢复为当前。
  - 两套订阅来源放在同一分区，后端模型不变。
  - 删除了重复的“全部 / 直连节点 / 链路”切换；节点页的 4 个统计改用四列布局。
- **后台刷新期间的点击（D12）：**
  - 按钮还没显示为禁用时被拦下的点击，显示约 3 秒的“操作未执行，请稍候再试”提示，不再静默忽略。
  - 表单遇到暂时刷新时只拦住提交，草稿仍可编辑。
  - 写保护语义不变，不排队延后执行。
- **按页面拆分代码（D15）：**
  - 管理页面按需加载，加载器使用普通状态更新，不经过 `Suspense`，页面显示不依赖计时器。
  - 页面样式按原层叠顺序留在主样式文件中。
- **离线告警（D14）：**
  - 迁移 `0050` 增加 `servers.last_contact_at`。
  - 正常断开时，`last_seen` 照旧提前 61 秒，让设备立即显示离线。
  - 离线阈值与告警事件的“最后在线”改用真实联络时间。
- **可维护性（D16 部分）：**
  - `ProxyUsers.tsx` 中 6094 字符的单行拆成结构化 JSX。
  - 本轮改写的 `Nodes.tsx`、`AdminShell.tsx` 等文件使用可读格式。
- **测试：**
  - 新增 Rust 集成测试 `offline_alert_threshold_counts_from_the_real_disconnect`：真实设备连接后断开，确认断开 60 秒时不告警、120 秒时告警，且事件记录的是真实联络时间。
  - 新增 Bun 单元测试，覆盖节点页分区路由、地址生成和导航分组。
  - 18 套浏览器回归按新结构调整：切换分区、在窄屏打开菜单、按隐藏状态读取导航属性、从文档根节点查找对话框。各断言的原有意图不变。

## 统一验证

环境：本机 Rust 1.97.0，PostgreSQL 16.14（专用临时实例，回环 55432 端口），Bun 1.4.2，Chromium 1194。

- **构建：** TypeScript 检查与 Vite 构建通过。主包从约 730 KB（gzip 219 KB）降到 265 KB（gzip 86 KB），不再触发 500 KB 警告。主样式文件中各页样式的先后顺序与原构建一致，`shell.css` 位于全局 `styles.css` 之前。
- **前端单元测试：** Bun 30 个文件、168 项通过，2267 次断言。
- **Rust 检查：** `cargo fmt --check`、全工作区全 targets Clippy（warnings 视为错误）、分层检查、`git diff --check` 通过。
- **Rust 与 PostgreSQL：** `sinan-panel` 全部 targets 共 69 组结果。
  - 首轮 548 通过、2 失败、7 条件忽略。两项失败是迁移数据保留测试的期望值没有登记新增列 `last_contact_at`；仓库惯例是在 `append_expected_server_defaults` 中登记后续迁移新增的列。
  - 补登后只重跑 `plugin_business` 目标：8 项通过、1 项条件忽略。
  - 合计 550 通过、0 失败、7 条件忽略，包括新增的 D14 用例。其他 crate 没有改动，没有重复运行全工作区。
- **浏览器回归：** 共 47 套；`passkeys.mjs` 需要由 Rust 用例拉起，不单独运行。
  - 首轮 35 套通过、12 套失败，原因如下：
    - 窄屏下收起的导航链接对 `getByRole` 不可见；
    - 暂停的假时钟让 `Suspense` 停在加载状态；
    - 菜单辅助函数没有等外框渲染完成；
    - `nodeHash` 在 `kind=chains` 且未指定分区时生成了 `view=catalog`；
    - 节点页统一快照让一个读取挂起时，其他资源也被拦住；
    - 两套测试的断言落在了被隐藏的分区。
  - 修复应用代码和测试后全量重跑，46 套通过；仅 external-access 失败。原因是我把代理用户页的外部授权区块移进了列表布局，用户列表清空时它被卸载，草稿随之丢失。已改回原位置，该套测试也改为从文档根节点查找对话框。
  - 随后补跑用到代理用户页的 7 套，全部通过；其中 admin-refresh 有 1 次失败，失败点在它对计时敏感的断言上，单独连跑 3 次均通过。这是 D13 已登记的偶发计时问题，没有因本轮修复而消除，不计为稳定通过。
  - 原先时好时坏的 proxy-resources、singbox-business 在本轮全量运行中都通过。
  - 节点页统计改用四列布局后重新构建；节点页相关的 12 套补跑全部通过，嵌入前端的 Rust `frontend` 目标也补跑通过。
- **截图：** 桌面节点页的三个分区、手机宽度的折叠菜单与各页内容已目视核对。
