# 诊断结束与清理确认验收

基线：`adde747e0960912e4f46bafdaa088d8fa76beb79`。本步骤集中完成 Agent 生命周期、协议、数据库、界面、回归代码和文档，全部修改后冻结，再统一验收。不进行修改期间测试；验收失败修复后只补失败或受影响范围。没有新建单项 PR、恢复 CI、正式签署/发布或生产部署。

实现约定见 [ADR 0049](../adr/0049-confirmed-diagnostic-completion.md)。自然成功/失败/服务丢失先固定报告与原始结果；低内存和期限先保存停止原因。清理未确认保留活动任务，重启只重试清理；面板显示“等待设备确认清理”，能查看已有章节和报告。取消和退役采用相同证据，退役清除凭据之前再次核实。

## 验收范围

- Agent/SQLite：原始成功、失败和 Missing 不被停止后的状态覆盖；停止失败、挂载/控制组残留、证据错误或挂起阻止完成与下一任务；重启和输出变化不丢固定报告、不重新执行；低内存和两种期限保持原因；状态查询挂起仍执行停止；存储失败保留所有权；九类目标损坏不能触发状态/停止/清理特权调用。
- 取消及退役：清理期间取消保留固定报告；自然终态与已持久取消意图串行；非 Running 不等于已清理；不支持、失败、超时和再次核实失败不能删除凭据或发送成功收据。
- 面板/PostgreSQL：cleaning 非终态、报告/章节保留、过期不释放、同机创建冲突、旧 Running 不回退、重连恢复、旧超时后的并发创建冲突、取消等待及迁移保留历史数据。
- 前端：一次构建后加载实际 dist；NodeQuality/TcpQuality 等待清理、原因与历史报告、禁止重复提交、取消接管、重启后恢复、确认后开放下一任务、390px 与桌面。
