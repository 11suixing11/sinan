# Release 发布身份保留验收

最终发布请求携带发布前已核对的标签和完整构建提交，不依赖服务端保留省略字段。固定 GitHub API 版本、完整签名与全部资产摘要、标签对应精确 main push CI（含 Reality）、发布前重新读取及发布后身份比较均保留。发布后竞态仍是检测，不能宣称原子发布或自动回滚。

本地对最终组合运行发布 24、旧 release 28、原生来源/签名 17、core 分层 6 项，共 75 通过、0 失败、4 既有条件跳过。公开 TEST_ONLY 密钥真实验证签名；GitHub 发布调用均为替身，不读取正式私钥或发送正式发布请求。用原主线 draft-only 发布函数运行同一新增行为夹具，确实因省略标签漂移而失去精确 release 身份；修复后通过。五类发布后并发变化仍拒绝报告成功。该模拟不证明固定 API 版本存在省略字段故障。

fmt、Python 语法、core 门禁与差异检查通过；运行代码及前端制品除发布 helper 外与 main 相同，不重复无交集 Rust/前端构建。本机没有进行 Linux 原生重建、专用节点实机诊断、正式签名、发布或部署。最终 head 的原生及常规 GitHub CI 单独跟进；实机阶段与正式发布仍受 [整改验收条件](ordered-remediation.md) 约束。
