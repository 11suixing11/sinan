# 遥测实时读取与分层历史：实现和本地验证

本次依据 ADR 0047，对照本地 NodeFlare 的 `agent/src/live.rs`、`live_batch.rs`、`shared/telemetry.rs`、`backend/src/websocket/ingest.rs` 和 `backend/src/db/queries/{ingest,history,rollup,maintenance}.rs`。保留 Sinan 的设备认证、SQLite 待确认队列、网卡整数账本和公开白名单，没有新增依赖。

## 采样、上传和持久化

现有 `AgentSettings` 保持严格旧格式。采样默认 1 秒，上传默认 3 秒，二者仍按原接口配置。新 `TelemetrySettings` 仅包含 `persist_interval_secs`，默认 60 秒，可设 15–3600 秒；通过独立接口协商，避免旧 Agent 因未知字段拒绝配置。每份新样本携带当次内存、磁盘容量，历史百分比不借用今天的硬件容量改写过去。

新 Agent 的三项工作独立执行：保存本地待确认样本、发布最新真实采样、上传持久批次。实时发布不移除待确认队列，面板明确只返回接收结果；原批次接口在收据、历史和网卡账本同一事务提交后才返回原有 UUID ACK。每次追补至多处理 16 个既有 64 样本批次，仍受单批大小、本地两小时、7200 条和 64 MiB 上限约束。断连超过缓存预算产生缺口，不生成零值填补。新协商接口不存在或配置无效时，Agent 回退原持久上传节奏。

实时缓存全局最多 16 MiB，单样本最多 128 KiB，十分钟未接收的条目不再使用。缓存不作为历史或用量依据，也不刷新心跳。重复、较旧采样不刷新其接收时间。面板重启、缓存淘汰或失效后读取最后持久样本，保留原采样时间，前端可据此显示陈旧。

## 历史与去重

保存策略默认 30 天，可设 1–3650 天。近两小时原始记录保留到分钟边界；分钟统计保留七天，七至三十天压缩为五分钟，更早压缩为一小时。压缩避开七天迟到范围并保留时间余量。默认 30 天时没有必要保存更老的一小时层；提高保存期限后该层开始生效。

Sinan 原协议接受七天内迟到样本，与 NodeFlare 的两小时重放范围不同。新增 `telemetry_receipts` 将设备范围内的 UUID 和原始规范化摘要独立保留七天加一分钟，不能随着两小时原始记录一起删除。相同 UUID、相同内容重复确认，内容不同返回冲突，整个批次回滚。旧的分钟末值投影仅作兼容，不参与新的平均数定义。

每项已知指标分别保存有效 `count`、`avg`、`min`、`max`，压缩与查询按各指标的有效样本数加权。缺少 CPU、容量、速率的样本不贡献该指标的计数；不存在的桶不返回虚构观测。`sample_count`、首末真实采样时间用于解释覆盖范围，迁移中只有分钟末值的记录按一个真实观测回填并标记 `partial`，不宣称完整分钟统计。回填流式读取旧数据，不截去超过固定行数的历史。

网卡累计字节只保存各接口最近观测值，并以十进制字符串返回，保留完整 `u64` 精度；它不是桶内用量，不能求平均或相加当作账单。账单仍由原 `server_network_counters`、`server_network_daily` 事务使用计数器差值和原重置规则产生。速率曲线只聚合已采集速率，缺少任一参与接口的方向时总速率未知。

资源告警另外保存按当时网卡选择规则筛选后的同刻速率之和，再计算其最小值和平均值。统计键绑定规范化选择字符串摘要；范围变化、缺失指标导致有效计数不足时，通知保持未知。不能把不同接口各自的最小值相加作为总速率最低值。此类内部统计键不进入公开历史。

独立维护任务约每分钟运行，不依赖下一次设备上报。过期清理、压缩、旧数据回填分别分配预算，每张表最多十个 2000 行短批次；整体异步超时覆盖阻塞等待，数据库事务另设语句和锁等待上限。未完成回填的服务器不能清理其原始或旧分钟来源。回填、接收和压缩遵循服务器行锁次序，汇总写入及源粒度删除同事务完成；繁忙服务器跳过后重试。

## 接口

所有新时间字段均为 Unix 毫秒；旧 `last_seen` 和 `last_heartbeat_at` 保持秒。

- `GET/PATCH /api/telemetry/policy`：管理员读取或设置 `history_retention_days`。
- `GET/PATCH /api/servers/{id}/telemetry-settings`：管理员设置历史写入间隔；新建服务器也接受该对象并同事务保存。
- `GET /api/agent/v1/telemetry-settings`：设备读取历史写入间隔。
- `POST /api/agent/v1/telemetry/live`：设备发送原 `TelemetrySample`，只确认易失接收。
- `POST /api/agent/v1/telemetry`：原有有界压缩批次和持久 ACK，旧 Agent 无需改变。
- `GET /api/dashboard/live`：返回 `served_at`、`public_view` 和完整可见设备 ID 集合及轻量最新值，适合三秒轮询。
- `GET /api/servers/{id}/history` 与 `/api/dashboard/servers/{id}/history`：接受 `window=15m|1h|2h|24h|7d|30d|90d|365d`，返回 `from`、`to`、实际 `bucket_ms`、`retention_days` 和 `points`。默认 1 小时。`bucket_ms` 不小于实际保存层，边缘统计覆盖超出请求时标记 `partial`。
- 原 `/metrics` 接口保留近两小时原始响应，避免破坏旧前端。

每个历史点包含 `bucket_at`、`sample_count`、`first_sampled_at`、`last_sampled_at`、`metrics`、`network_counters`、`partial`。`metrics` 是指标名称到 `{count,avg,min,max}` 的映射，缺失键保持未知；接口不补零、不插值。历史大批读取设上限，超过时返回忙碌，不静默截断成貌似完整的历史。

完整服务器响应和轻量实时响应区分 `metrics_sampled_at`、`metrics_received_at`、`metrics_persisted_at`、`served_at`。其中 `metrics_persisted_at` 是最近已持久保存样本的采样时间，不是提交或 ACK 时刻。

公开读取每次重新检查公开开关及隐藏状态，并返回 `public_view`。管理员会话退化为公开访问时，前端可立即丢弃原管理字段；隐藏设备从实时 ID 集合消失，历史返回未找到。公开指标和历史均使用白名单，网卡名匿名化，容量及采样间隔可读，设备密钥、内部额外字段、网卡选择摘要、自动更新配置不公开。响应统一禁止缓存。

## 本地验证与未验证范围

定向检查覆盖：

- 协议保留旧配置格式，独立写入间隔上下界。
- Agent 的持久 ACK 阻塞期间实时发布仍可执行，待确认样本在 ACK 前不删除；旧面板缺少新接口时回退旧上传。
- 既有采样超时、陈旧缓存、恢复、时间单调和 SQLite 待确认队列回归。
- PostgreSQL 迟到、重复摘要冲突与整批回滚、原始清理后的幂等性、`u64` 网卡账本、加权统计、分层压缩及重复维护。
- 超过首批八台服务器的回填保护、持锁维护预算、离线保留期清理、新建设备写入设置的原子校验。
- 实时接收不等于持久保存、晚到不覆盖新值、公开白名单、隐藏和关闭公开立即生效。
- 历史边界实际分辨率、同刻多网卡求和的极值和选择范围隔离。

测试使用专用回环 PostgreSQL 和本地 HTTP 夹具，未向外部设备或生产库写入。长期大规模高频负载、真实网络长断连、生产升级和多平台常驻 Agent 尚未验收；CI 保持暂停，未部署。
