# NodeQuality r14 Netflix 请求与页面判定修复

关联 Issue #123；独立分支基于 PR #118 的 `c316bfcf6654e3ea3abc734aa3526157da7775a6`。本项只修复固定 IPQuality 的 Netflix 判定，不并入 #120 的浏览器请求头、#121 的公共 cookie 或 #122 的凭证来源整改。PR 先以 #118 分支为目标，待前序合并后再统一整合主线。

## 缺陷与复现边界

固定 IPQuality 提交为 `87397e2c3196ec796f5477c83343c2354df601ea`。旧函数在 `local result=$(curl ...)` 中丢失退出状态，把标准错误并入正文，再以是否包含 `Oh no!` 判定。向原函数的 curl 桩注入错误文本、返回 22，确实会得到成功；只执行抽取函数，不运行上游初始化、硬件测试或外站请求。

真实回环 HTTP 另有一个重要区别：保留原参数的 `curl -fsL` 会静默处理本次 403，没有错误正文，因此该特定场景下旧函数已经返回失败。测试没有加入 `-S` 来人为制造旧逻辑失败。相反，真实 HTTP 200 的非预期访问页面会被旧函数误报成功，新函数拒绝。这两类证据分别保留，不把错误桩的行为扩大成所有真实 403 都误报。

## 修复内容

新增 `netflix-policy.py`，在 r13 评分策略之后对固定字节做唯一锚点变换。声明变量与执行请求分开，分别保存两次 curl 的退出码和最终 HTTP 状态；仅在两次请求都成功且正文符合保守的影片页面格式时，才交给既有分类。标准错误不再参与正文解释。

403、429、其他非 200、超时、DNS/连接/TLS 错误、未完成传输、空正文及未识别页面都显示失败并附具体原因。原因按两个影片分别记录，既进入文字报告，也进入 `Media.Netflix.Reason`。合法结果保留既有成功/仅自制分类、地区与解锁类型；JSON 的地区值只保留双字母，避免页面数据被直接拼入查询表达式。

两次请求仍对应两个不同影片，不是重试。保留原 GET、每次 10 秒预算、接口选择及 TLS 参数，不通过换 UA、添加 cookie 或凭证重试。新增 HTTP 状态输出和 2 MiB 文件上限；另校验已返回正文大小，不把这个后置检查宣称为所有 curl 版本都具有严格的流式内存上限。

包装器、面板插件版本及制品工具同步到 r14，保留 r2 至 r13 的历史报告读取与原模式兼容。完整任务门禁保持；本项没有改数据库、删除历史结果、修改其他流媒体查询或启动真实上游执行链。

## 专项验证

`tools/test-nodequality-netflix-policy.py` 的 14 项在 Debian 12 隔离容器通过，使用真实 Bash、curl、jq 和本机 HTTP 服务。17 份原始来源按既有清单核对大小与摘要；通过实际 source-helper 取变换后的源码，只执行抽取函数及自有夹具。

验证包括错误文本负对照、真实 403/429/截断与 10 秒超时、真实非预期页面负对照、先成功再失败、不复用当前旧字段、合法分类/地区保留、长页面在 pipefail 下不误判、文本/JSON 原因、其他媒体/评分字段保留。新失败任务发布章节后，旧成功任务及其原文件字节保持，其他章节仍可读。helper 缺失、篡改、符号链接、FIFO、超限、非法变换输出、输入与输出摘要、唯一锚点及构建拒绝均有断言；完整变换后的源码通过 `bash -n`，没有执行完整脚本。

首次烟测有两项夹具失败：Python 字符串把用于分隔测试输出的 `\0` 解释为实际 NUL，已改用原始字符串。随后真实 HTTP 负对照暴露上述静默 403 的差异，修正的是测试假设，不是通过增加 curl 标志改变复现。首轮组合的静态数据逆变换和报告编排夹具没有接入新增策略，分别导致一个断言失败、两个初始化错误；补齐逆变换和固定锚点后复测，没有放宽既有字节一致性断言。原始失败日志保留在工作区外的私有验证目录。

Rust 适配器 15 项通过，0 失败/忽略；包含 r2 至 r14 的 full 启动拒绝、历史章节读取、版本不匹配拒绝及日常模式参数保留。workspace 格式检查与该适配器全 targets Clippy（warnings 为错误）通过。初始构建镜像缺少 rustfmt、离线注册表缺少依赖，以及无额外权限的 root 不能写入宿主用户拥有的缓存，均作为环境失败保留；改用专属工具镜像及工作区用户，在单独下载已锁定依赖后断网执行验证。没有在宿主安装工具或修改原构建镜像。

## 未验收范围

正向页面是明确标注的合成格式契约，不是当前 Netflix 页面或实际播放能力的在线验收。页面结构变化时采取未知/失败，不能据此承诺所有地区、所有真实页面都会被识别。没有访问 Netflix、查询其他 IP 服务、执行完整 NodeQuality 或压力基准，也没有使用公共 cookie、抓取新凭证或接受外部许可。

本轮没有正式签署、发布、部署或恢复 GitHub Actions。新增的 CI 测试命令仅在日后统一恢复流程后生效；暂停状态不能记为 CI 通过。供应链、rootfs、专有工具授权、其他上传路径、取消与持续代理流量的完整实机矩阵仍按原问题分别验收。

## 主线整合的独立复核

本聊天以公开作者提交 `072edf9e3c6afbc16edd627b1cace677dc668abf` 为输入，普通合入主线 `33a3085484bc7c3e1e61c9e558134585c3e44921`。上文 Debian 容器、资源峰值和作者组合收据仍仅对应作者冻结输入，本聊天没有重演该环境。固定 17 文件共 687,969 字节、八个策略 helper 摘要以及 r13 输入/r14 输出均按实际 source-helper 重新核对；Netflix helper 及其变换后的源码字节未改。
