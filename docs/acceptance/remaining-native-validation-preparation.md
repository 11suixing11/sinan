## 最终冻结后执行方案

`tools/prepare-plugin-install-acceptance.py` 只在干净已提交源码上生成新宿主私有 namespace，保存 Git 归档、完整输入摘要、原 r3 已审核生命周期脚本摘要和新配方；不连接 Guest、不构建、不签名、不安装或执行测试。它保留旧输入和收据，拒绝覆盖输出。准备脚本本轮尚未执行。

#130 后续可沿用 r3 的真实空配置安装配方：新 namespace 的独立 PostgreSQL/面板/Agent 服务、真实固定 ARM64 运行时、TEST_ONLY 信任根、缺制品拒绝、显式启用与幂等、签名安装与健康回执、Agent 重启、面板短暂断连、心跳和 runtime fingerprint 连续性；最后 finally 清理并核对 PID、cgroup、端口、模板、账户、boot/SSH/swap 和 OOM。仅替换受审核配方的私有根，不重用旧二进制或旧结果。

#63 可复用同一冻结源码构建出的 Agent/面板二进制，但使用独立 namespace、数据库、端口和收据。专用 Guest 内存与磁盘有限，不同时构建或运行两套验收；#130 安装配方会占用受保护的标准运行时模板与账户，因此其 finally 清理及基线复核完成后再运行 #63。低资源、持续自有回环代理、重启 outbox、120 秒断连停止调度等属于 #63 自己的真实实机收据，不能用 #130 的短暂断连替代。

#58 的 `tools/prepare-native-tcp-acceptance.py` 只保存最终干净 Git 源 bundle、摘要与待执行配方。优先在现有远端隔离 Debian 12 构建环境运行原生 amd64 musl 固定配方，使用最终明确的完整 Git commit、locked 依赖、真实 ELF/version/build-info、五个辅助文件、完整原文与 TEST_ONLY 重签/篡改拒绝测试。源只读、新输出及 target 私有、网络关闭；资源上限 2 CPU / 1536 MiB / 无额外 swap / pids512。执行开始前独立核对镜像内的 Debian 12、工具版本、musl 目标及离线依赖；缺失时记录缺口，不在线自动补依赖。新制品路径必须为空；保留历史 b562 字节和配方。ARM64 工具不足应明确报告，不能把 amd64 结果冒作双架构通过。

#6 的原验收 shell 明确要求 amd64、Docker 和真实 systemd，因此不能直接在缺 Docker 的 ARM64 Guest 运行，也不能仅修改架构检查后称为同一验收。可在隔离 amd64 测试环境保留原 shell，或另写明确范围的 ARM64 原生回环 Reality 配方；两者都需实际固定运行时、真实双向载荷核验和失败时独立诊断，禁止输出载荷、地址、凭据或原始配置。生产、公网长期稳定性和未定位的历史失败单独记录。
