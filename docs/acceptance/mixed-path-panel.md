# 混合链路面板与发布状态验证

日期：2026-10-01。本地隔离 PostgreSQL 18.6，证据代码为 `crates/panel/tests/mixed_paths.rs`，通过 `cargo test -p sinan-panel --test mixed_paths` 执行七项测试。所有服务器、设备结果和来源均为测试夹具，不接触生产数据库或真实机场。

| 验证项 | 覆盖行为 |
| --- | --- |
| 原子批量与重放 | 同批多个入口自动分配不重复端口；任一参数或端口冲突整体回滚；相同 UUID/摘要返回原收据，不同内容拒绝；删除后收据仍保留。 |
| 发布和订阅门槛 | 内部依赖先准备，候选探测、切换、复验、全设备恢复屏障和旧代清理按顺序推进；订阅只输出已确认的公开入口，不暴露内部身份。 |
| 能力与失败 | 旧设备等待升级；新增能力后自动补发此前未准备的依赖；候选失败保留旧路径或关闭尚未成功的初建入口；明确重试产生新代。 |
| 外部段更新 | 中间 HTTP 来源密码更新产生不可变版本；应用期间后续刷新不修改冻结版本集合；失败保留旧代，指定新版本后成功推进，旧身份等恢复确认后清理。 |
| 部分恢复屏障 | 一台设备已经确认下界后，另一台能力丢失不撤候选身份；明确停用撤销所有已发出的代数，不依赖尚未写入面板的最终下界。 |
| 引用、名称与退役 | 受引用端点不能直接改监听参数；管理名与订阅名分开；投影更新不改历史部署 `source_json`；入口服务器退役后仍能查看和删除链路，清理共享内部身份并保留历史。 |
| 有界验证队列 | 批量链路共用设备时最多同时排队四项探测，每项五分钟，后续链路等待容量，不一次生成大量即将过期请求。 |

测试直接注入设备的应用与探测结果，以验证面板事务和推进条件；不能据此声称 Agent 已在多台机器上执行这些步骤。真实原生三/四段转发及 Clash 探测分别见[本地网络夹具](mixed-path-local-fixtures.md)，Agent 的签名绑定、持久下界、恢复和结果重放见[通用运行时验证](runtime-validations.md)。

上线前仍需在授权的专用设备执行签名整包发布、候选失败/断线、切换期间重启、部分屏障确认后故障及撤销场景，并确认真实入口计量只记一次、旧版本恢复受限、服务与临时资源无残留。正式发布与生产迁移未执行。CI 按当前安排继续暂停，未执行不记为通过。
