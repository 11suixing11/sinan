## 统一测试发现的 TCP 产品缺陷

原运行期报告发布使用探测截止作为原子写盘截止；接近截止时真实 fsync 会直接报错，跳过已预留的最终报告发布。现在已开始的原子发布使用同一总截止，worker 整段探测独立受探测截止约束，截止后不再开始连接。停止/join 后排空最多 16 条已排队更新，保留实际尝试和完整 snapshot，并补写对应章节；I/O 错误仍传播，总预算和单次 I/O 上限不增加。

CLI 与引擎共用绝对截止，工作区检查不重启计时；原 60 秒总预算内保留标准输出时间，再从引擎预算保留报告发布时间。新增仅测试构建存在的 gate 在实际 write_all 后、sync/rename 前跨过引擎真实探测截止，验证连接已停止、任务仍能保存 partial、真实尝试没有被标成未执行、章节与总报告一致且无 pending 文件。原截止规则的负对照稳定失败，修复后 15 个库测试和 4 个 CLI 测试通过。
