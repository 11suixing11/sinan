## 真实 Debian 材料取得：部分完成

执行环境为专用 LIMA Debian 12 ARM64 虚拟机：2 CPU、1536 MiB 内存、8 GiB 磁盘、无 swap、无宿主目录挂载。外层收集单元使用 256 MiB MemoryMax、64 TasksMax、低资源权重、独立挂载和临时目录。实际 APT 求解另进入只含回环接口的网络命名空间，执行 update 和下载 URI 规划，没有安装包或运行维护脚本。

固定请求是 Debian main `20261001T142720Z`/bookworm 与 security `20261001T142623Z`/bookworm-security，构建时间 `1790864840`。实际导入列表精确匹配；最后一次取得 8 个 HTTP 200 元数据对象，通过 InRelease、Release SHA256 与四份压缩索引认证。使用独立核对来源的 Debian archive keyring；Bookworm main 的两个允许指纹及 security 指纹满足认证条件。keyring 中其他已知签名用于完整 GPG 验证，不扩大原 Bookworm 允许范围，见[收集说明](../nodequality-rootfs-collection.md)。

三次实际尝试均保存失败原件：

1. 仅含 Bookworm 三把主密钥的 keyring 无法完成包含额外已知 Trixie 签名的 GPG 验证；只读离线诊断确认签名正文相同，随后采用独立核对的完整 archive keyring，认证指纹范围保持。
2. APT 安全仓库 URI 没有可选展示校验和，原解析器拒绝。修复该兼容问题后补验 collector 26 项；实际数据摘要仍必须与签名索引匹配。
3. 选择出 237 个二进制包，预计 98,800,644 字节，对应 168 个源码名称/版本对；完整来源闭包超过显式 900 MiB 总材料预算，收集器在首次包/源码正文下载前主动拒绝。源码总字节未写入失败收据，公开记录为未知，不重算或编造数值。

因此尚无成功的 `collection.json`、完整 `materials.json` 或候选输入锁；没有 builder 审批、rootfs 构建、双架构复建或完整 NodeQuality。下一步需要为工厂闭包安排足够的独立容量及明确预算，再集中完成实际输入取得；设备的 256 MiB 外层制品预算不能随工厂容量一起放宽。

## 资源、清理与尚未验收项

两次 Linux 契约单元的内存峰值分别为 67,645,440 与 64,839,680 字节；三次真实收集分别为 44,974,080、163,876,864 与 162,316,288 字节。每次收尾核实无 OOM、所属进程、挂载及 cgroup 残留，SSH 在各自单次基线中没有重启；失败缓存有界保留用于追溯。

宿主曾出现 ENOSPC，导致最后一轮浏览器尚未启动、已完成的 guest 日志暂时无法取回；空间在只读检查期间恢复，原因未知，没有删除现有文件或停止外部进程。浏览器随后首次启动，guest 已通过项只取回日志，没有重跑。第三次实际收集前另检测到 guest boot 身份变化，原因未知；先拒绝启动，经专用 VM 配置、系统、keyring 与缓存复核后记录新基线。不能将所有尝试描述为同一次 guest 启动。最后一次收集增加私有宿主容量守卫，运行期间未触发。

指定的 aws-jp0 仍在 SSH banner 阶段超时，lucius7 可达但其到该机 TCP 22 超时，未在该节点执行本步负载。恢复 SSH、核对低内存拒绝以及完整 Agent/sing-box 联合负载仍待；不改用生产节点反复压测。

本步不认证完整 NodeQuality 的硬件负载、生产面板部署、原生双架构 rootfs、第三方工具许可或真实混合机场链路。Geekbench 与 Ookla 条件、完整 Agent/sing-box 联合负载及故障矩阵保持独立待验；既有全量 Rust 收据仅属于其原冻结输入。CI 继续暂停。
