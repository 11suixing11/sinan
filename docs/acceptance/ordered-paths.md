# 有序混合链路与版本发布验收

日期：2026-10-02。整步源码与本地集中验收完成；[脱敏机器收据](ordered-paths-local.json)记录最终输入、逐例去重结果及失败尝试。架构与具体出站验证依据见 [ADR 0056](../adr/0056-ordered-path-publication-and-native-probe.md)。按照用户要求，先集中完成修改，冻结后统一验收；修复期间暂停验证，最终只补验失败或受影响范围，最后一次提交整步。

## 本步骤实现

代理节点页统一管理直连及链路资源。新链路是一个独立公开入口加 1 至 8 个有序受管或外部节点，批量最多 32 条；外部引用来源身份 epoch、明确节点、不可变版本和成功批次。完整向量写入不可变版本，跟随只跟随同身份同节点，固定版本只由管理员明确选择。同机、重复端点、循环、无效身份、容量和原生编译不满足时拒绝整批，重复 UUID 返回原收据。

发布依次准备内部接受身份、确认受管依赖、准备入口候选、具体出站验证、切换入口、验证切换结果、固定恢复屏障，再撤销旧身份。公开订阅要求当前完整向量及具体运行实例的确认，粗粒度 apply、旧 checkpoint 或迟到探测不替代。设备已承诺屏障但回执迟到时，保存最低路径代数，不能在更高配置 revision 中重新发布低代路径；没有当期完整确认仍不标为成功。

当前、候选及恢复向量一起保护受管节点和来源，删除保留墓碑、历史和幂等收据。旧两跳通过初次捕获保留入口、relay、订阅与旧配置语义，不补造探测事实。账本旧 `Vec<Node>` 和新版来源快照均可读，内部接受身份及探测不进入代理用户计量。策略组和单独授权统一读取资源，专用链路入口不另列为直连。

## 集中验收结果

首次集中验收的 Rust 类型、排版和 Clippy 失败日志保留。完整 r6 回归收齐 28 个失败后修复共享 policy SQL、发布 RR 事务并发 `40001`、普通节点 ABI 制品误锁与旧夹具合同；发布仅重试未提交的完整事务，通知只在提交之后发送一次。取消 socket 回归消除本组并发端口抢占窗口，仍立即只重绑一次并检查保留 poller/地址失效；原日志缺少失败地址，不能追认当时的实际占用者。

后续收齐失败发现共享服务器推进使旧证明成为 `superseded` 时被误判网络失败，现保留原回执、清自己的关联并要求当前完整向量的新请求。回归明确验证新证明前订阅仍不可用、旧 UUID/接收时间不改。孤立请求不能重标向量；屏障之前必须有当前完整探测；未知屏障不撤旧或降低代数。r8 其它场景通过后，最后一项夹具的手动阶段发布时序集中修正，r9 只补该例和受影响 Clippy，迟到屏障的安全拒绝逻辑保持。所有 PostgreSQL 与所属 socket 已停止并清理。

真实流量夹具采用两阶段：专用 Linux 节点生成 TEST_ONLY 密钥、证书及端口输入；冻结 checkout 的 Rust compiler example 输出 A／M／B／客户端配置；再由 Linux 运行该输出。Python 只创建受控 X 和目标，不手写产品链路图。单机多个受控进程需要搬移既有统计端口及客户端监听端口，保存原产品配置、改后配置及每项变换摘要，并分别做 native check。实际流量证明对应搬移端口后的产品编译图，不写成未经变换的 Agent 正式部署、真实账本事务或多台生产服务器安装证明。

具体出站 HTTPS HEAD 不验证响应 status，也不返回出口 IP。probe 成功、真实出口、逐跳经过、UDP 和完整持续业务负载分别记录。所有失败 attempt 保留，最终验收修复仅补验失败或受影响范围；代码和实际 dist 摘要随机器收据固定。

原生首轮发现 example 的 HTTP 中间层 `path: "/"` 使实际 CONNECT 目标不正确，现采用原生默认空 path；只修该夹具输入，保留 transport 及具体出站校验。实际二进制未声明可选 `with_grpc`，源码证明存在默认 lite 和可选实现；只移除夹具不必要的 feature 条件，产品编译器对尚未认证的 gRPC 参数能力仍保守拒绝。两轮原日志、固定上游源码与摘要保留；最终实际流量收据 SHA256 `c51607e9db8b7ed17401e9cb8fdf8e2bf5317532224a4bd238aafe8a5c6aaee8`，guest 证据归档 SHA256 `c13eb573815f5e80c3d439bc707fc4c12e0816034edab46a3c9dac0eeca555f3`。
