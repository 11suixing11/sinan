# 整改顺序与验收状态

实施拆成独立 PR，实机能力验收按以下顺序推进。每项 PR 保存自己的问题、改动范围、源码身份、验证结果和未通过项。源码可以在独立审查及相称验证后合入准备；源码合入、实机能力签收和正式发布/部署分别记录。前置阶段未通过时，不签收、不正式发布或部署新增诊断能力；已有后续代码或绿色 CI 不代表对应阶段通过。

下表汇总的既有证据以主线 `d1ff2dfdea3cc45b38fd0dd25ef6a5b189081b1e` 为基线；TCP 后端 #77 和报告页 #78 的原审查基线分别为 `58868c4`、`233840a`。后续源码整合与检查以各 PR 最终提交及对应 CI 单独记录，不将这些基线当作最新主线、实机能力签收或正式发布证明。CI 结果只对其实际运行的提交和场景有效。

## 故障矩阵

每个阶段都逐项说明下面场景是否适用、具体执行方法与证据。确实不适用时写明原因，不静默省略。查询故障用于来源适配与诊断中的查询章节；不要求无查询能力的资源属性接口制造第三方查询。

| 场景 | 必须观察的结果 | 当前证据与缺口 |
| --- | --- | --- |
| 小内存 | 启动前明确拒绝；运行中内存保护停止诊断；Agent、已运行代理和心跳仍正常 | 预检/运行保护测试、systemd 限额夹具及专用节点 OOM 基线分别记录。基线是失败复现，不能算整改后保护通过；专用节点总验待补 |
| 磁盘不足 | 准备或持久化失败有具体原因；不伪造完成/ACK；旧任务、报告与账本仍可恢复 | 预检、账本和持久化故障注入已有测试。受控小文件系统上的节点复核待补，禁止填满宿主共享磁盘 |
| 查询 403、429、超时 | 单源错误可辨；记录目标、时间和耗时；不绕过限制或暴力重试；旧成功结果保持 | 面板环境实际 403、受控 HTTP、PostgreSQL 持久化与浏览器错误夹具分开记录；429 和超时夹具不表示真实供应商已解除限制 |
| Agent 重启 | 不重新执行已不确定启动的诊断；恢复原检查点、报告和待取消意图；账本不重记 | 真实 Agent/面板 WS/HTTP 与两种数据库恢复夹具、CI Agent 服务重启及 runtime HUP 有证据；完整 NodeQuality 负载中的节点重启待补 |
| 面板断连 | 心跳/连接恢复与采集缓存独立；补传受条数、字节和调度预算约束；章节和取消确认可重放 | 回环 WS/HTTP、SQLite 重开与有界积压测试有证据；专用节点完整负载断连待补 |

## 专用节点恢复后的执行次序

1. 在云控制台恢复已指定的专用节点，读取当前内存、磁盘、systemd 与连接状态。此前停止并禁用了原代理业务且保留配置；此前服务健康快照不能证明恢复后状态。最近记录的只读探测在 SSH banner 阶段超时，未进入认证或执行负载。
2. 保留 447 MiB 配置用于低内存拒绝验收；完整任务默认预算为 512 MiB，另需 256 MiB 可用内存预留，因此不得在该配置上绕过预检。完整负载须增加内存并重新核实 MemAvailable。
3. 先解决完整执行链：固定入口、实际脚本、rootfs 和辅助工具；核实所有分发许可；证明没有未授权上传、宿主 swap 或网络改动。现有完整门禁在该条件满足前保持。若改用有限的自有测试，须先明确能力范围，不能默认为原 NodeQuality 完整能力已保留。
4. 部署与验收记录一致的 Agent、面板、插件和签名制品，读回实际 systemd 预算与常驻保护。使用独立身份、数据库和已获准的测试目标；正式业务凭据不进入日志。
5. 在专用节点建立持续代理流量与基准心跳，然后逐个串行执行故障场景。测试磁盘使用独立受限文件系统，测试负载使用有界单元，不影响其他服务器。每次结束先核实清理，再开始下一次；不因负载失败立即反复重跑完整测试。
6. P0 独立通过后依次签收 IP、业务迁移和 NodeQuality 框架，再执行 P2 接入的实机验收与能力签收。各阶段代码可以先完成独立源码审查和整合；每个阶段最终整合提交都需要自己的实机证据，旧提交的绿色结果不认证新部署。

## 每次实机验收必须保存的信息

- 源码提交、Agent/面板/工具版本、制品摘要、签名身份、实际任务参数及 systemd 资源属性。
- 开始/结束时间、诊断前后负载、MemAvailable、工作目录磁盘、`systemd-cgtop` 和内核 OOM 差异。失败原始证据保存在私有目录，公开摘要脱敏。
- 实际 Heartbeat 消息的接收时间和最大间隔、设备指标的采样时间及过期标记。普通设备消息的 `last_seen` 不能代替实际心跳；旧指标不能伪装成最新采样。按预先确定的心跳条件验收，不通过调大离线阈值掩盖间断。
- 持续代理请求的成功/失败、进程 ID、NRestarts 与运行时状态。只检查服务 active 或做一次请求不足以证明整个诊断期间业务正常。
- 取消请求、Agent 清理结果及面板收到的成功清理确认；主/控制进程、cgroup 子树和任务相关挂载的最终读回。取消时已有章节仍可读，未确认时界面仍显示等待。
- Agent 重启、面板断连后的恢复、outbox 重传与最终报告完整度；重复提交和部分报告分别有结果，不只保存一张成功报告截图。

测试通过、条件跳过、未执行和失败分别记账。当前专用节点总验未完成，目标仍为待完成状态；续费、账单日网卡配额、周期拨测及代理套餐周期属于之后的独立任务。
