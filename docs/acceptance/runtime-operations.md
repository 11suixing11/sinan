源码对应 ADR 0043。当前只做隔离本地验证；GitHub Actions 继续暂停，未运行的 CI 不属于已验证项。生产迁移、发布和真实设备验收未执行。

## 本地验证

- `crates/agent-core/tests/reconcile.rs`：明确重启拒绝旧修订、无效签名、prepare 失败和末次计数器失败；健康失败执行原回滚；成功重启保留配置版本。连同原对账、恢复、合并及签名测试共 11 项通过。
- `crates/agent-core/tests/services.rs`：固定单位查询、日志窗口和路径注入拒绝；连同原服务管理测试共 7 项通过。
- 协议上限/未知参数 1 项、Agent 结果重放、执行中断与时钟舍入下界 3 项、PostgreSQL 鉴权/设备隔离/终态不可改写/期望版本/退役 2 项均通过。回执已被面板接收但响应丢失时，本地结果仍能主动重放。测试仅使用本机隔离数据库与回环 HTTP 夹具。
- 前端 TypeScript 和生产构建通过；`web/tests/runtime-operations.mjs` 桌面/手机状态日志、确认重启、运行中互斥、旧目标拒绝及旧 Agent 能力提示通过。既有 `node-settings.mjs`、`singbox-business.mjs` 浏览器套件通过。
- `tools/check-core-boundary.py` 通过。通用 Agent 代码不含具体代理业务名。

## 专用测试机人工步骤（未验证）

1. 新旧 Agent 分别打开节点部署弹窗及服务器插件区：旧版不可执行运维，新版按钮可用；关闭本机任意远程命令后仍可读取状态与执行固定操作。
2. 各系统按真实部署方式产生包含测试凭据的服务日志。确认响应只有时间、级别和固定分类；Windows 标明计划任务事件，未声称采集标准输出；超量输出、长行和读取失败准确显示截断或不可用。
3. 保持实际连接与有账本流量时重启，检查短暂中断、末次计数器、epoch 与累计量；正常配置健康后才显示完成。
4. 失败配置应用后手动重试当前期望版本。发布新目标与点击重试并发时，旧请求不得切回旧版；不可信制品或配置 prepare 失败不得启动。
5. 重启失败、健康失败与回滚失败分别注入；重启 Agent 后验证原 intent 恢复与未完成运维请求报告中断，不能重复执行一次操作。
6. 在执行期间断开面板、重连、重复上传结果，确认历史终态不变；开始退役后不能领取或启动新运行时操作，正在执行的操作与退役顺序等待。

这些步骤尚未完成；本地替身和 PostgreSQL 测试不能替代上述实机验收。
