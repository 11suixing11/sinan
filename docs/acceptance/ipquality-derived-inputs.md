有效用例共 117 项，全部通过。隔离单元实际设置 MemoryMax=256 MiB、MemorySwapMax=0、TasksMax=64、CPUWeight/IOWeight=10、OOMScoreAdjust=500；仅 lo、独立网络与挂载命名空间均有实际记录。各次结束后所属单元、进程、挂载、cgroup 和临时目录清理，SSH 进程、启动身份与零 swap 基线保持。

首轮夹具缺少 Debian `Essential: yes`，产品因此正确拒绝，修复只补合法包字段及其真实摘要链。另一夹具增长正文导致先触发大小限制，改为等长字节变更以验证所需身份守卫。制品构建的 Linux 验收则发现真实 `MemoryError`：`gzip.read(2 GiB + 1)` 对小归档也申请巨大缓冲。修复 gzip 与 tar 成员均每次最多读取 1 MiB，累计上限、CRC、完整尾部、路径与库存约束保持；此上限是单次读取量，不是总内存占用承诺。

专用 Debian 虚拟机对真实旧缓存仅尝试一次离线派生。父材料由内核设为只读，重新验证后，在 APT 启动前的展开容量准入以 `factory free-disk reserve crossed` 拒绝，退出码 1，耗时约 9.84 秒；未创建派生成功收据。拒绝时剩余磁盘 670,830,592 字节，保留 536,870,912 字节管理空间及 1024 个 inode，新输出峰值实际占用 163,840 字节。MemoryPeak 为 268,435,456 字节，`memory.events.max=7631` 表示发生回收压力，`oom/oom_kill=0`；没有把可回收缓存估计当作可用内存承诺。失败收据保留，所属输出已删，旧三份父记录摘要保持，结束后剩余 670,846,976 字节、无进程/挂载/cgroup 遗留。

本轮没有降低预留、隐式扩容、清理旧材料或重复尝试容量拒绝。实际最小选择、正向派生及后续工厂能力仍待容量充足的独立环境。现有 501 份 Rust/前端输入及 19 份已构建 dist 相对 `c6ffbdb` 逐字不变，沿用前一步证据，未重复运行 Rust、Bun、浏览器或前端构建。core 分层和 diff 检查通过。

## 输入和来源

派生只读取一份完整的旧 NodeQuality Debian 12 收集目录，在新的私有目录产生独立 IPQuality 材料。旧收集记录、官方 snapshot import 响应、材料、索引、包和对应源的实际字节均须重新核对。父记录中的 `complete`、来源已认证等声明不能代替本次认证；架构必须与明确选择的原生架构一致。

父链须同时保留 `materials.json`、`collection.json`、`request.json`、`keyring-provenance.json`、`unbound-inputs.json`、原 `solver/selection.json` 和 `capacity-plan.json`。原求解清单的包选择不含缓存 `blob` 字段，须精确对应父材料；原容量清单的包和对应源须与父材料一致，并由旧收据绑定实际原文件摘要和大小。核对旧清单并不把旧容量观察当成本次可用资源。

固定 snapshot 时间仍由原始 import 响应证明，不能选择邻近时间，也不能复制一个成功 HTTP 状态到未发出的请求。新派生必须明确记录父材料和收据的身份、派生过程及新材料的身份。它是一项本地缓存派生，不能只替换旧 `kind` 来冒充新网络收集。父目录保持只读，旧证据不被改写或重新解释为新下载。

最小包选择使用 IPQuality 独立工具配置及对应的依赖闭包。选中的每个二进制包、对应源版本和源文件必须是已经认证的父材料中的精确子集；版本、架构、仓库、路径、大小和摘要均须一致。缺少必要包、源或父证据时拒绝派生，保持未知，不下载缺失内容，也不扩大为完整 NodeQuality 镜像。

源码策略、工具配置、原缓存和派生记录所引用的文件必须是有界、普通、单链接文件；不接受符号链接、FIFO、跨目录路径或身份在读取期间变化的文件。新增清单与父记录都绑定实际文件身份和摘要，不以示例摘要、声明或 URL 代替真实字节。

## 输出、容量和失败

新目录独立保留派生记录与所选材料，缓存通过受身份约束的父引用只读外借，不创建新的 `input-cache` 目录、硬链接或软链接。准入核算求解器必要的索引与镜像副本、展开目录、临时文件及最终记录；外借缓存不冒充已复制到新目录的字节。字节预算、磁盘管理保留、inode 管理保留和可用内存都须满足。运行期间继续按截止时间和动态守卫检查，不能在开始时检查一次后无限写入。

默认磁盘保留至少 512 MiB、inode 保留至少 1024，宿主 `MemAvailable` 保留至少 256 MiB；cgroup v2 的非空 `memory.events` 观察和 OOM 基线必须明确。未知观察拒绝继续，OOM 或 OOM kill 计数变化停止派生；`max` 压力单独记录，不把文件缓存可回收估算当成硬可用内存。

新输出包含独立的 `derivation.json`、材料、profile、父输入身份清单、代码清单、工具证据、认证展开边界、求解记录、容量计划及完成时的 `factory-capacity.json` 和 `memory-observation.json`。失败证据在保留容量允许时单独保存有界错误与清理结果；保存失败仍保持未确认，不为补写证据重跑派生。

拒绝、超时、中断和错误只清理本次取得所有权的新目录；旧父目录、旧缓存、已存在的输出和与本次无关的材料须保留。目录被替换、仍有挂载或所有权无法确认时，拒绝盲目删除并记录清理未确认。容量计划是保护依据，不能宣称它是内核硬配额、来源认证或 builder 审批。

派生后的 bind 必须重新核对派生记录、父身份、子集及真实输入，再检查明确给出的原生 builder 候选。bind 只产生候选绑定，不批准 builder，不安装宿主软件，不执行诊断，不把 `builder_approved`、完整能力或复现验收标为成功。

入口为 `tools/ipquality-inputs.py derive --materials <旧收集目录> --output <新目录> --max-output-bytes <预算> --timeout-seconds <截止秒数>`，随后使用 `bind --derived-inputs <派生目录> --candidate-builder <候选文件> --output <另一新目录> --timeout-seconds <截止秒数>`。`tools/ipquality-rootfs.py` 提供相同派生入口；旧 `bind --materials` 路径保留原语义。新 bind 会重新运行离线求解并要求结果仍等于既有子集，不能仅凭旧选择文档批准候选。

## 验收场景与约束

| 范围 | 场景 | 必须观察的结果 |
| --- | --- | --- |
| 父记录 | 不完整、错误 kind、错误架构、材料摘要变化、未绑定收据或旧求解/容量清单变化、失败记录残留 | 在派生前拒绝；旧材料不变 |
| import 响应 | 空列表、重复 archive、额外 archive、时间漂移、正文缺失或被替换 | 固定时间证据不完整即拒绝；不选择临近 snapshot |
| 本次认证 | 父 receipt 曾标成功，但索引、包或源正文已变化 | 对实际父字节重新认证；不能仅相信旧布尔字段 |
| 最小子集 | 精确选中 deb/source、额外源、版本或架构漂移、缺必要输入 | 仅输出精确闭包；缺失保持未知且没有下载 |
| 文件安全 | 软链接、硬链接、FIFO、跨目录、读取时替换或增长 | 普通单链接和身份约束生效，失败不接受旧摘要 |
| 来源记录 | profile、工具或策略变化，父路径或身份迟到变化 | 派生清单核对失败，不能伪造新 HTTP 收据 |
| 新输出容量 | 总字节不足、可用磁盘不足、inode 不足、宿主可用内存不足 | 准入拒绝，不清理旧材料腾空间 |
| 动态保护 | 写入时空间下降、宿主可用内存下降、cgroup 观察未知或 OOM 事件增加、截止时间、主动中断、输出目录被替换 | 停止派生，记录失败，只清理本次已确认所有权的目录；保留被替换的无关材料，明确记录清理未确认；cgroup 文件缓存不冒充实际内存不足或可回收硬承诺 |
| bind | 子记录篡改、父身份变化、候选工具变化、错误原生架构 | 重验证失败；合法绑定仍不批准 builder |

单元夹具使用真实计算的字节摘要、普通文件身份和有效字段关系。昂贵的原生操作及外部认证接口可由明确的隔离替身代替，但其通过结果只证明拒绝与记录逻辑，不证明官方 GPG 签名、真实 APT 求解、命名空间隔离或 builder 审批。

## 仍待真实原生节点

本轮真实尝试已经保存对应源码、原命令结果、资源、失败与清理证据；磁盘准入拒绝不能算正向派生通过。容量充足的专用 Debian 12 环境仍须完成实际最小选择与派生，再另行完成原生 builder 审核、prepare/build/export、逐包许可证与完整对应源审查、签名和节点故障矩阵；这一派生步骤不替代它们。

缺少实际 builder、完整最小源制品、匹配签名制品或 Agent 能力时，节点自查继续不可创建，未知结果不显示为成功。未完成实机签收时不发布或部署新能力，不解锁完整 NodeQuality，不关闭相应待验事项，也不宣布整体整改完成。CI 保持当前暂停安排。
