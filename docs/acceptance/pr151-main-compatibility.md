# PR #151 主线兼容整合

本记录描述本聊天的源码整合；当前仍处于实现阶段，尚未运行这次整合的测试、构建或检查。作者原分支的验收和私有设备记录保持各自的冻结边界，不能认证本次整合输入。

## 不可变数据与 API

旧主线 0001–0039 迁移、数值订阅来源及外部节点版本、数值混合链路版本和原凭据保留。新建 0040–0045 迁移登记运行时确认、节点 IP 章节世代和 UUID 有序链路；不改旧迁移的摘要或把两套外部节点编号互相转换。作者原分支的旧编号数据库需要单独迁移安排，本聊天未升级该私有数据库。

现有 `/api/plugins/sing-box/subscription-sources`、`/subscription-source-jobs`、`/proxy-resources` 与 `/chains/batch` 保留主线契约。新 UUID 来源使用 `/ordered-subscription-sources` 和 `/ordered-subscription-source-jobs`，丰富有序资源使用 `/ordered-proxy-resources`，创建使用 `/chains/ordered-batch`。管理界面继续在代理节点页统一呈现；内部版本表与接口身份分开，公开入口不因列表合并而重复或失去引用保护。

旧两跳链路创建同时登记新只读冻结投影；旧数值发布仍负责其部署，有序发布只处理 `path_kind=ordered`。两种路径在一个发布事务中组合为同一个配置包和 revision，保留原数值路径的单入口计量和授权。需要共用私有探测控制时，新发布事务将两套编译器的控制身份统一到一个新 revision；旧部署与恢复证据保持原字节，不能用新凭据认证旧在途请求。

入口、受管中间段及出口的创建、编辑和删除交叉检查两套引用，包括尚未确认清理的已删除有序链路。清理确认之前，入口不会在旧列表或丰富列表中重新成为独立节点。归档、替换或缺失来源停止新引用和自动跟随；已经冻结的有效版本继续保留，不能将来源刷新失败改写成历史运行失败或自动换出口。应用状态和真实连通性仍由各自的确认流程核对。

## 诊断与拨测

主线周期拨测继续使用 `Probe.monitor` 内的精确许可身份、来源、范围、线路、地区、地址家族、期限及会话租约。离线新撤销需要同步，旧 Agent 接收禁用投影，旧 JSON 和历史保留；没有把作者旧授权原型代替主线的发送前复查和单调截止。

原 NodeQuality r19 通用执行与 r20/r21 节点查询保持各自原版本和签名文件身份。新原生和最小 IPQuality 路径使用独立版本/制品身份，不给旧版本换一组不同字节。r2–r21 的 full 新启动、旧排队和缺字段默认门禁、精确 Started 恢复及取消确认继续保留。新的 IPQuality 章节经任务身份、世代与事务验证，使用隔离的来源前缀；原面板查询和旧节点查询缓存保持可读。
