# 精确运行确认、恢复屏障与链路编辑保护验收

日期：2026-10-02。本步骤源码及本地验收完成；实际 Linux 服务、完整联合负载与整体整改签收仍待验。机器证据见 [冻结输入与逐用例结果](evidence/runtime-checkpoints-and-chain-guards.json)，架构见 [ADR0047](../adr/0047-runtime-checkpoints-and-recovery-barriers.md)。

## 本步实现

- 面板为不可变部署生成稳定身份；Agent 核对实际 current 引用、普通配置文件完整字节/清单、bundle 摘要、独立签名运行时和受控进程。Linux systemd 后端核对 MainPID、InvocationID、cgroup、boot/starttime、exe 和单个绝对配置参数，读取有界、前后稳定；其他后端不填造精确身份。
- 成功 apply 建立稳定 activation；同一部署的成功/失败收据复用操作身份，避免周期轮询抖动及日志增长。相同配置的新版本保留实际未重启的 activation；原绝对配置参数稳定，解析后的版本目录单独严格核对。
- checkpoint/barrier 请求和结果先持久化；ACK 匹配 UUID、kind 和请求摘要，未确认结果不按 TTL 删除。有界后台工作不占连接循环；设备补传及面板事务后 ACK 保留原结果，迟到、被替代或失败事实不能推进当前健康/恢复阶段。
- 恢复屏障把单调最低 revision 与成功收据在同一 FULL SQLite 事务提交；此后 apply/rollback/recovery 均守下限。被下限阻止时保留 intent、错误与管理连接，不吞数据库、身份或全局信任错误。请求期限最长600秒；设备日志最多4096个不可复用ID、256个未确认项，每行16 KiB、单轮16项/64 KiB，满时拒绝新增并保留已有工作。
- 检查与屏障不隐式恢复或重启业务。旧库缺少 activation、或受控进程自行重启后旧记录失效，同版本保持拒绝且无服务动作；管理员明确发布严格更高版本可受控 Restart 并重新认证，签名、bundle、版本下限与目标健康检查保留。
- 两跳链路按钮、开窗和创建/删除处理器均检查 chains/nodes/servers 新鲜读取；失败/pending 保留旧列表及草稿并暂停写入，关闭/重试可用。恢复后检查消失/停用节点或服务器、协议、入口/出口角色和消失链路ID；允许明确清理仍存在但不可用的旧链路，共享出口保留。没有新增在线或安装就绪门禁。

原代理用户、节点/链路 ID、凭据、订阅路径、计量及部署历史不迁名或重写。数据库仅增加控制辅助表。现有用户、授权、套餐、节点和两跳链路继续属于 sing-box 插件；本步没有机场订阅解析、混合路径、实际候选/切后路径探测或分阶段 publisher。
