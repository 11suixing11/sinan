# 统一分支与查询读取验收

2026-10-01，统一分支正常合入主线 `86e2ef4`，合并提交 `6d9513c`，最终受验代码 `c8cea16`。不新建单项 PR。独立来源、失败与补验记录保存在[证据索引](evidence/unified-query-r17.json)，不以本项补签整个整改目标。

sing-box 保留“服务器接入 → 明确启用并安装 → 节点/链路 → 代理用户与授权 → 设备应用确认”。同时保留主线插件目录、服务器插件页、延迟任务、通知和 GitHub Agent 接入逻辑。安装迁移在未正式发布的统一分支改为 `0021`，让已入主线的 `0019` 延迟任务和 `0020` 通知保持原身份；安装 SQL 原字节不变。生命周期 ADR 改为 `0041`。旧安装验收实际执行过 `0019`，没有改写旧收据来追认新的迁移编号。

r16 不再下载公共 cookies，也不使用网页临时 key 或嵌入的 Disney 授权发起请求。ipregistry、DB-IP 和 Disney 保留报告位置，明确显示未配置授权查询方式、信息未知；没有发请求的来源记录 `Attempted=false`、空 Attempts 和 `last_attempt_at=null`，判断时间另存。DB-IP 的未知评分与因素保持 null。

r17 将主线 Netflix 页面校验接在固定 r16 输出之后，保留 r15 的 Error、Attempts、目标 IP、实际耗时和首失败停止。Netflix 和匿名 YouTube 都在进入 Bash 变量前限制原始输出至 2 MiB 加 128 字节尾部；正文再限制至 2 MiB。管道等待生产者退出，沿用十秒请求截止时间；截断、缺少完整尾部或读取器失败时不编造退出码、HTTP 状态或耗时。没有 cookies、浏览器身份或新增重试。

Netflix 校验 HTML/title、当前影片 URL 与影片 schema，保留原不可用影片页面的有限判定；附加字母的影片 ID、登录或挑战页均为未知。原 marker 分类对 grep 的无匹配退出码显式处理，使合法页面在严格 Bash 下仍能保存报告。页面夹具通过不证明真实播放或当前公网页面契约。固定 canonical 源码、完整许可证和报告能力保留；旧层隔离只在测试夹具中，生产没有旁路。

Debian 两次最终单元实际读回 256 MiB、Swap0、Tasks64、CPU/IOWeight10、OOM500、私有网络/挂载、control-group 清理及 240 秒上限。组合 r2 用时 141.997 秒，补验 r3 用时 20.326 秒；内存峰值分别 69,255,168 和 61,014,016 字节，峰值均 11 个进程，内存 max/oom/oom_kill 均零。结束没有测试进程、挂载或 cgroup，SSH PID406 未重启、同 boot、swap0，磁盘保留阈值满足。

真实有限 chunked 负对照确认：Debian curl7.88 仅用 `--max-filesize` 时完整读取 4 MiB。新读取器在 2,097,280 原始字节截断，传输确认字段保持 null；原参数和测试中去掉 curl 限额的独立读取器两路均验证生产者回收。DNS/连接/TLS错误使用惰性桩，HTTP403/429/超时、chunked 和正常传输使用自有回环，没有公网供应商请求。

保留了所有已知失败：早期读取上限缺口的独立审查；报告夹具漏锚点；多行 JSON 被误读产生的 37 个子例错误；命名空间检查在测试前拒绝；旧 Type 期待错误；新层漏隔离；Netflix strict/URL 边界审查；大场景环境变量触发 E2BIG。原收据不重写。最后一项仅改为私有、普通、有界场景文件，没有缩小原 100000 字节 padding 或移除严格正例；之后 17 项实际补验全通过。

本项没有运行完整验机、实际播放、正式制品发布、生产迁移或部署。用户确认没有 Geekbench Pro 许可，原完整能力的[工具与许可条件](nodequality-full-tool-prerequisites.md)、离线 rootfs、节点自查适配、持续代理负载故障矩阵和注册后的原生 TCP 整链仍待验。所有版本的 full 门禁保持，四个源码 CI 工作流仍为 `disabled_manually`。旧安装实机收据也不认证新 GitHub Agent bootstrap 或当前整合版本的实机部署。
