# Cloudflare DDNS 插件主线整合与验证边界

本节对应 PR #138 作者推进 `014631bb` 的 DDNS 源码与主线普通整合，按 [ADR 0048](../adr/0048-cloudflare-ddns.md) 接入。旧监控分支和旧主线的 Rust 599/20、631/20 验证均不覆盖本次新增 DDNS；当前实现阶段未运行测试、构建或格式检查，最终验证由整合任务统一执行并绑定实际冻结源码。

## 整合补修

- Cloudflare PATCH 按当前[官方编辑接口](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/edit/)发送已核对、保持不变的 `name/type` 与 `content/ttl/proxied`。不发送 `comment/tags`，不改他人的备注或标签；首次创建使用本规则 UUID 标记，并核对回执标记以支持远端成功而本地回执未落库后的再次读取恢复。HTTP 成功且 `success=true` 不能覆盖同时出现的非空 `errors`。
- Zone/记录列表读取完成后，在真正写入前重新验证规则租约 UUID、修订、启用、设备未删除/退役、在线、十分钟报告以及本次地址仍在当前报告中。只有实际写入阶段持有本地规则和服务器共享锁；领取/停用使用同序的数据库 advisory 锁。退役/删除的服务器行更新和规则编辑等待已开始的有界写入，不会在确认后重新启动旧写入。
- 先以独立语句取得服务器行共享锁，再用同事务中的下一条语句读取退役状态，避免等待退役事务期间保留旧的 READ COMMITTED 语句快照。完成回执同时匹配租约和原修订；编辑清除旧租约，迟到成功/失败不能覆盖新修订的目标、状态或重试时间。
- DDNS 候选地址单独补排 IANA 文档段 `3fff::/20` 与基准段 `2001:2::/48`，以及退役的 IPv4 `192.88.99.0/24`；原共享 IP 查询分类行为不变。依据 [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/)和 [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/)。不粗排 `2001::/23` 下有更具体分配的所有地址，不把这些范围当真实 DNS 目标。
- 429 `Retry-After` 接受非负十进制秒和 HTTP 日期，日期小数向上取整，保留 60–3600 秒的现有有界等待；负数、带符号和无效值使用固定默认。重试从本次实际完成时间计算，未知错误只返回本地固定码，不回显 Token、目标请求或上游错误正文。

## 回归源码与未验证范围

已有私有回环提供方夹具保留创建、明确接管、重复/CNAME/NS 拒绝、IPv6 语义、TTL、局部更新、去重、权限与凭据脱敏。新增回归源码覆盖两个读取阶段之间的离线/删除/报告过期/地址变化/租约丢失均零 DNS 写入；等待退役事务后读取新快照；写入期间服务器与规则锁；旧修订的成功和失败回执不覆盖新状态；特殊地址报告零提供方请求；HTTP-date 和矛盾错误回执。

本地事务不能撤销已提交给 Cloudflare 的外部写入，也不能认证各地 DNS 缓存传播、实际 Token 权限或接收方的绝对即时停写。请求超时后可能已在远端生效，下轮须先读取并对账，不能承诺跨系统恰好一次。暂停/删除规则仍不删除远端记录；真实凭据、测试域名 DNS 写入、地址变更、长期运行与生产迁移均独立待验。本任务没有真实 Cloudflare 请求、正式制品签署、发布或部署，CI 持续暂停。
