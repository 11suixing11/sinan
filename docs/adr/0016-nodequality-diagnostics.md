# ADR 0016：IP 质量与节点诊断外插

## 决策

按用户新增需求，在已完成的 MVP 上加入 NodeQuality 外插。Agent 上报网卡 IPv4/IPv6；NAT 节点可在 Agent 配置中指定公网地址。面板依据上报地址查询 NodeQuality 所用 IPQuality 的数据库 API，并缓存结果。数据库质量信息与在节点实际执行的完整报告分别呈现，失败与数据缺失不能冒充成功。

诊断属于一次性任务，不使用代理配置的声明式版本和流量周期。公共协议定义固定外插任务及状态；Agent 入口注册无状态诊断适配器。core 负责任务持久化、同源制品校验、独立 systemd 服务启动、恢复与结果重传。适配器只翻译固定选项、准备服务参数及解析报告，不持久化、不连接面板。所有特权操作仍经过 Privileged，所有服务操作仍经过 ServiceManager。

诊断通过固定白名单选项执行，不提供远程命令或 WebSSH。每台节点同时最多一个报告任务，使用任务 UUID 保证重连和重启不重复启动测试；最终结果入库后才确认。任务拥有明确超时，服务控制整个进程组。CPU、磁盘和带宽测试只在管理员点击获取报告后运行。

NodeQuality 启动脚本从固定上游提交制作制品，Agent 仍从面板下载并校验 SHA256。用户明确要求节点测试，因此原 ADR 0010 的外网限制对该诊断外插作必要例外：外插运行上游测试时可访问其依赖、测试及报告服务；Agent 原生传输和代理运行时制品仍只从面板获取。上游 chroot 是测试环境清理方式，不是针对恶意脚本的安全隔离。外插是可信管理员选择安装的原样上游程序。

面板复用 workspace 已有的 reqwest HTTP 客户端；新的 adapter-nodequality 仅依赖 adapter-sdk 和既定 anyhow/tokio。没有新增依赖库种类。界面、部署和开发构建继续使用 Bun。

## 替代方案

不在 Agent 心跳中阻塞执行测试，不让 Agent 直接启动长期子进程，不将诊断混入运行时对账和用户流量账本。只展示安装命令不满足“一键获取报告”，任意 shell 参数不符合固定外插与现有特权边界。

## 验证边界

通过受控 HTTP API、数据库、固定脚本输出和服务夹具验证查询、分发、恢复、去重、失败与报告回传。在未提供真实 Linux 节点时，不将这些自动测试称为真实 NodeQuality 性能或带宽验收。真实 systemd 的独立服务、失败和超时测试在 Linux CI 单独执行，其结果以对应提交的实际流水线为准。
