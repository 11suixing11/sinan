# ADR 0031：暂缓 NodeQuality 不受控完整任务的新执行

- 状态：临时安全门禁；不是完整工具链整改完成。
- 关联：Issue #28、#65、#66。

## 原因

固定入口仍会下载在线 main、执行内层公开上传，并在低内存分支修改宿主全局 swap。r5 的正常退出修复没有改变这一依赖链；上传顶层设置关闭、systemd 内存限制和挂载隔离都不能消除这些副作用。详细固定提交、摘要、许可证缺口与模拟证据见 [执行链审计](../acceptance/nodequality-chain-audit.md)。

完整能力的保留或删减需要用户决定。在离线签名依赖、网络行为与宿主副作用得到独立验收之前，所有当前版本的完整任务禁止新执行；不改已发布 r2–r5 不可变工具字节，不用删减后的探测冒充完整 NodeQuality。

## 决策

- NodeQuality 插件负责完整模式的拒绝理由、界面可用性和调度能力规则。共用服务只调用登记插件的 `start_denial`、`can_dispatch`，不加入 NodeQuality 参数规则。
- 两种创建 API 都拒绝新的完整任务。既有排队完整任务记为失败并保存原因，不置 `agent_completed`，允许迟到章节、报告与确认式取消，也不永久阻塞日常检查。
- 未声明 `diagnostic:nodequality-full-start-gate` 的旧 Agent 不再收到完整任务的队列/运行重发。新 Agent 的适配器在创建目录、调用工具或启动服务之前拒绝完整模式；声明此能力的 Agent 可以恢复自己的 Started 检查点收集、清理或取消。
- 已有 Started 检查点继续只观察和回收，不重新执行。r2/r3 的旧选项与 r4/r5 的模式元数据都保留，报告身份与签名制品版本不改写。
- 日常检查继续使用已固定的标准库轻量探测和逐源 IP 缓存；64MiB/32tasks、256MiB 启动预留、2GiB 磁盘与运行保护不降低。界面明确显示完整验机暂停的原因，不把历史顶层上传开关称为零外部上传。

## 发布边界

面板不能撤回门禁上线之前已返回给旧 Agent 的 HTTP 任务，亦不能消除旧 Agent 已在 Preparing/启动阶段的副作用。上线前需升级 Agent 或对已领取任务取得取消确认；未完成这一步不能宣称旧 Agent 的全部新启动都已阻止。已运行任务保持可回收和可取消，不以数据库失败状态冒充设备停止。

后续受控完整工具必须发布新版本并经过独立验收。此门禁不关闭上述三个 Issue，不证明原版内层零上传、rootfs 授权完整或完整负载验收通过。
