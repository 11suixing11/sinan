# ADR 0020：链式中转的内部凭证、入口计量与依赖发布

- 状态：采纳设计，尚未实现。
- 范围：第 5 阶段仅交付本文，不增加链路代码、接口、数据库迁移或空模块。
- 目标：未来支持“用户客户端 → 一个托管入口 → 一个托管出口 → 目标地址”，两段均使用 VLESS + Reality。每个入口只选择一个出口，每台服务器仍运行一个运行时实例。出口池、外部出口、任意多级链路、自动故障转移和计费不在本次设计内。

## 拓扑与编译边界

管理模型区分公开用户入口、内部出口监听、入口到出口的有向关系。内部出口不属于用户 `accesses`，其流量固定直连目标；它不能继续转到另一个托管出口。多个入口可共享出口监听，但每条关系必须使用独立内部凭证。出口服务器上的其他公开节点可为直接连接的用户正常计量。

写入模型和编译时均拒绝自环、重复关系、同一入口多个出口、跨已删除或正在退役的对象，以及服务器依赖图中的环。即使某个环暂时不会产生数据面循环，也不允许引入循环发布依赖。第一版拒绝超过一次托管中转的路径。被入口引用的出口、内部监听及所属服务器不能直接删除或退役；应返回包含受影响入口的依赖冲突，先显式切换或停用这些链路，再进入既有删除/退役流程。不能静默回退为直连。

编译输入由 `Vec<Node>` 扩展为带 schema 版本的 `ServerSnapshot`，分别表达公开入口、内部监听、链路出站、路由、出口投影及用户计量名单。内部监听即使没有终端用户也必须保留，不能沿用当前“`users` 为空就跳过”的判断。全服务器监听端口统一检查冲突，继续保留本地统计接口端口。

每台服务器仍产生一份完整配置包。编译器不查询网络或数据库，不生成随机凭证；所有集合按稳定 ID、角色、generation 排序，输入相同则原生字节相同。协议和 SDK 仅表达通用依赖及探测结果，具体出站、路由和原生计数语法仍在 compiler/adapter 中。适配器保持无状态，恢复与持久化由 core 负责。

两端 Agent 必须同时满足兼容协议范围，并明确声明支持链路快照、统计角色过滤、依赖探测及恢复边界的能力。缺少能力或不认识快照 schema 时拒绝该操作，保留原配置，不能忽略链路字段后把流量直连。正式能力名称和消息字段在未来实现时随协议变更固定，并以兼容测试验证。

## 内部凭证：独立生成，逐步切换

### 身份与秘密存放

面板为每条链路的每个 generation 生成独立随机 UUID，沿用当前授权使用的安全随机 UUID v4 来源；在事务中先保存，再参与编译。初始 generation 为 1，之后单调递增。禁止由用户 ID、链路 ID、时间推导 UUID，禁止复用终端用户 UUID，禁止共享出口的不同入口共用凭证。

内部认证名字采用 `relay_l<link_id>_g<generation>` 一类固定命名空间，不符合用户计量名字语法、不包含 UUID，并且永不写入用户统计名单。UUID、Reality 密钥和 short ID 分别承担认证与握手职责，不能互相代替。

内部 UUID 明文只保存在面板的秘密配置数据以及确有需要的两端运行配置中；只存摘要无法生成两端配置。面板列表、普通日志、错误、用户订阅和发布 outbox 只记录 ID、generation、摘要与状态，不复制秘密。数据库、备份及 Agent 配置目录沿用现有秘密配置保护方式；本文不引入未定义的密钥管理服务。出口私钥只进入出口配置，入口仅取得该端点公钥和自身链路 UUID。

管理员触发轮换后，面板只允许同一链路保留旧、新两代有效凭证；前一轮尚未结束时拒绝开始下一轮。旧代撤销后不得重新启用或复用 generation。历史配置和备份可能仍含旧秘密，撤销只表示出口不再接受它，不等于擦除了历史副本。

### 持久轮换状态机

区分三类版本：凭证 generation 标识 UUID，端点 generation 标识监听与握手参数，依赖 generation 标识一次链路依赖变更。凭证或端点改变都会推进依赖 generation；只改运行时兼容参数也会推进依赖 generation，但不强制重生成 UUID。下文的阶段确认必须绑定这三者的完整组合；“最低可恢复 generation”指依赖 generation，不可只比较凭证编号。

下述五步描述 UUID 轮换；端点变更复用准备、探测、切换与恢复边界，兼容版本变化则至少完成重新求解与本轮探测，不虚构需要撤销的旧 UUID。

阶段为 `stable → preparing_exit → preparing_entry → switching_entry → retiring_old → stable`。数据库保存两端目标及已确认 revision/hash、凭证和端点 generation、探测请求与结果、当前阶段及失败原因。超时保持阶段和旧凭证，不自动当作成功。

1. **准备出口。** 在事务中锁定链路和相关服务器，生成 pending UUID 并创建持久发布待办。出口完整快照同时接受旧、新两代，入口仍使用旧代。出口必须确认本轮配置已持久应用且健康；确认匹配链路、generation、revision 和配置摘要。
2. **从入口验证候选路径。** 出口准备完成后，发布入口准备快照：保留用户使用的旧出站，同时加入候选出站和只用于有界探测的路径。探测须由入口机器发起，明确选择新 UUID、新端点，经真实 Reality 认证并访问受控目标；只测 TCP 端口打开不合格。探测不能借用终端用户身份，不能进入用户统计名单。
3. **切换入口。** 探测成功后才发布入口切换快照，将用户路由切到新出站。入口确认对应 revision、配置摘要、generation 已持久应用，并再次通过新路径完成实际流量探测。失败时仍允许回滚到旧代，因为此时出口仍接受旧代。
4. **固定可恢复状态。** 入口成功后，面板要求入口持久确认依赖的最低可恢复 generation。Agent 仅在当前已应用配置使用新代、健康验证通过且没有可能恢复旧代的未完成 intent 时确认；保存最低 generation 后，自动恢复/回滚不得再选择低于该边界的快照。确认丢失可从持久状态重放。这个步骤不会改变用户 UUID 或重置已有计量基线。
5. **撤销出口旧代。** 只有该旧代的所有消费者完成上述确认，面板才发布出口撤旧快照。出口应用且健康后完成轮换。第一版每个内部 UUID 仅对应一个入口；共享出口也必须逐条关系核对，不能用其他入口的确认代替。

初次建立链路没有旧代：先准备出口和候选探测路径，验证成功才让公开入口使用该链路。更换出口服务器也按同一流程先准备新出口；在入口完成恢复边界确认前保留旧出口关系和凭证。

探测需要未来新增的通用 SDK 能力。设计选择在同一运行时配置中提供仅回环可达、明确路由到候选出站的临时探测入口，由 Agent 发出有时限、有大小限制的请求。回环地址只限制网络可达性，不是授权边界。每次探测必须使用独立、高熵、安全随机生成的认证秘密，不复用用户或链路 UUID；秘密仅供 Agent 和受管运行时读取，不进入普通日志、错误、订阅或发布 outbox。本机其他用户即使知道探测端口，也不能通过它使用候选出站。

探测凭证必须有短有效期，完成、取消或超时后立即失效，并随完整快照移除临时入口、认证和路由；Agent 崩溃或重启不能让未完成探测变成长期代理。Agent 自身请求的超时和大小限制不能代替入口的认证有效期及清理。运行时路由还必须只允许本次受控目标的明确目的地址和端口，拒绝其他目的地址、端口及默认出站回退，不能仅靠 Agent 自愿访问固定 URL 来限制用途。

它不使用第二个长期运行时或任意 shell 命令。上述认证、有效期、清理、目标限制，以及实际选择候选路径的行为，都须由未来真实运行时验收证明；不能假定上游已支持某种未验证的配置，也不能假定当前健康检查已有该能力。如果某运行时无法执行这些限制，就不能启用该探测方法或据此确认链路就绪。

入口离线、准备失败或探测失败时，面板保留旧状态；出口已准备的情况下保留双凭据，显示阻塞原因。出口撤旧失败时继续接受双凭据并重试，不能提前显示完成。入口已固定最低 generation 后，后续故障应保持新代并报告故障，不得自动越过恢复边界回到旧代。若数据库或设备从更旧备份恢复，必须重新核对双方 generation 与恢复边界，再允许发布。

未切换用户路由前允许取消轮换，但必须确认入口未使用候选代，再移除其探测配置和出口候选凭证。切换后按状态机完成，或执行新一轮有序变更。离线入口会延长旧凭证存活时间；疑似泄漏需立即撤销时，管理员必须明确接受相应入口断流并记录紧急撤销，不能称为无损轮换。

### Reality 密钥与端点变化

UUID 双接受不代表 Reality 私钥能双接受。上游配置为单个 Reality `private_key`，而 short ID 可为列表；当前编译器也是单私钥。本文因此不设计在同一个监听上同时接受新旧 Reality 私钥。[上游 TLS 配置](https://sing-box.sagernet.org/configuration/shared/tls/#reality-fields)

换私钥、公钥、SNI、地址或端口时，使用新的端点 generation，并在同一运行时保留旧监听、增加不同端口的新监听，按前述屏障逐个切换受影响入口，最后回收旧端点。旧地址在过渡期必须仍可达。单独轮换 short ID 可利用上游列表并存，但仍须等入口确认后撤旧。

如果必须保留唯一固定地址和端口，无法同时提供两套握手配置，则安排明确维护窗口；不承诺零中断。运行时升级或完整配置重载也可能影响既有连接，分阶段发布只能避免凭证次序错误，不能据此宣称所有 TCP 会话无损。

## 计量：只记录用户认证入口

公开入口使用终端用户 UUID 认证，继续以 `u{user_id}_n{entry_node_id}` 记录累计 uplink/downlink；向出口连接时使用内部 UUID，不转发用户 UUID 或用户统计名字。出口只认证链路身份，因此同一用户流量只在入口进入用户账本。出口上独立公开节点的直接用户流量仍按其自身用户和节点计量。

编译器生成明确的 `accounting_users` 集合，并将其中的用户名字写入运行时 `stats.users`。集合只包含本机公开入口上的终端用户授权；内部监听、内部出站、探测身份以及 inbound/outbound 总量都排除。入口路由只允许选定链路，出口失效时不自动直连。

当前适配器已有“按已应用配置的统计白名单过滤”机制，未来应扩展角色校验，确保名单本身只来自公开入口授权。正常内部计数忽略；伪装成标准用户名字但不在该快照名单内的计数也不入账，异常可计入无凭据的运维诊断。core 继续接收通用过滤结果，不解析原生 JSON。切换前的末次采样使用旧快照名单，随后使用新快照名单；保留成功 RPC 缺失用户补零、RPC 错误不补零的现有语义，避免计数重置后同样大小的新流量被漏算。

面板保持第二层验证：标准用户名字、发送服务器、用户与入口节点必须属于该服务器历史发布的用户计量授权。直接提交内部身份或未授权名字时，整批拒绝、事务回滚、不确认；不能删掉错误记录后确认同一个 batch，否则会改变其不可变内容。内部流量应在 Agent 生成并持久化用量批次之前排除。

### 对计量表和历史数据的影响

`usage_batches`、`usage_records` 的结构、完整 `u64` 值域和现有去重键保持不变。不创建假用户，不把 `user_id` 变为可空，不添加“是否计费”字段。换出口保持入口 node ID、用户 UUID 和统计名字稳定；节点仍不迁移所属服务器，以保留历史授权检查和离线重放的归属。

需要改变的是历史授权的来源：新 `ServerSnapshot.accounting_users` 明确保存 user ID、entry node ID 和标准统计名字；旧 `Vec<Node>` 仍按原路径读取。订阅与计量验证须兼容两种历史 source 格式，不重写旧快照来消除旧格式。保存的计量授权属于不可改写的历史事实，不能随显示名称或公开地址变化被覆盖。

当前发布器在原生字节不变时原地更新 `source_json`，未来必须区分可更新的订阅展示投影与不可变的历史计量授权、依赖和轮换证据。可以保留原 deployment 的不可变 source，并以单独的公开展示投影记录更新；不以覆盖旧 source 来伪造新一代已应用证明。用户账本无需为此增加内部链路字段。

第一版不新增内部流量统计表。链路探测状态、generation 和错误保存到发布运维记录；将来若需要出口总量，另用独立运维指标存储，不混入用户 `UsageBatch`，不将加密开销重复分摊给用户。

## 出口变化：反向依赖与事务发布待办

面板保存明确的入口到内部出口关系及反向索引。每条关系使用的出口投影包含：出口服务器/监听身份、地址、端口、SNI、公钥、该关系的 short ID、凭证 generation、端点 generation，以及影响握手兼容的运行时版本/能力。UUID 影响完整编译源摘要，但只以 generation 或秘密摘要参与可记录的依赖标识，原值不写入 outbox 或日志。

对版本化且稳定排序的投影计算 SHA256。投影变化时，在同一数据库事务中查找全部受影响入口、记录新的依赖 generation 和发布 outbox，并按稳定顺序锁定相关服务器；多个出口操作必须遵循统一锁顺序。出口上的无关用户授权、显示名称、遥测或最后在线时间不在投影中，不触发所有入口重编。共享端点的 host/port/key/SNI 改动影响全部引用者，某一关系的 UUID 轮换只影响该入口。

最小新增持久模型如下，均为未来设计，不在本阶段创建迁移：

| 模型 | 保存内容 | 关键约束 |
| --- | --- | --- |
| 内部出口及端点版本 | 服务器、监听、端点 generation、旧/新端点及秘密配置 | 全服务器端口唯一；有引用的端点不能删除；旧端点保留到所有消费者确认 |
| `managed_links` | 入口、出口、当前/目标 generation、阶段及投影摘要 | 每入口最多一条有效关系；出口反向索引；禁止循环和已退役对象 |
| `link_credentials` | link ID、generation、UUID、pending/active/retired 状态 | UUID 唯一；最多两代有效；不关联用户授权 |
| `publication_outbox` | 稳定去重键、目标服务器、阶段、依赖 generation、源摘要、所需及实际 revision/hash、探测/恢复边界确认、错误 | 业务修改与入队同事务；重试幂等；旧任务不能推进新 generation；不含秘密 |
| 公开展示投影 | 用户订阅所需公开入口信息 | 与不可变计量授权和依赖证据分开，不能暴露内部拓扑或凭据 |

固定状态机由上述记录表达，不引入通用工作流引擎。`servers.dirty_at` 继续合并单服务器配置变更，outbox 表达跨服务器次序和屏障。worker 从数据库恢复未完成任务，WebSocket 只负责唤醒；面板重启、断线、重复消息或通知丢失均不能使待办消失。

出口目标修改后，先准备并确认出口，再标记入口 dirty；入口只能消费已就绪的出口投影，不能直接读取尚未应用的 desired 字段。编译提交前用行锁和 generation 条件更新确认源输入仍有效，禁止旧任务清除新 dirty、确认新代或撤销仍被使用的凭证。第一版对同一链路轮换期间的新破坏性编辑返回明确冲突，无关变更可在保留当前阶段要求的前提下合并。

### 配置版本、源摘要和证据

完整 `source_hash` 覆盖版本化编译输入及依赖闭包；`bundle_sha256` 继续只标识实际配置包。出口投影变化必须持久触发每个受影响入口重新求解和编译，但入口原生字节相同时复用既有 revision，不为显示“发布过”而制造无意义重载。依赖记录与本轮探测结果仍须更新，不能借用上一轮的成功。

每个确认匹配 link ID、generation、阶段、两端 revision/hash、端点 generation、探测请求 ID 和实际运行时兼容信息。仅比较 `applied_rev >= required_rev` 不够：更大版本可能已经移除了所需凭证；须确认该已应用快照仍满足本轮接受集合。过期 ApplyResult、心跳或探测只可修复对应旧记录，不能推进新阶段。

现有 Agent 会跳过中间 revision，不能依靠“曾发布准备版”推断其已应用。发布器必须在收到当前阶段的精确确认后才允许产生下一阶段目标；后续同阶段快照也必须保留本阶段接受集合和探测能力。凭证回收只能由这些屏障推进，不由 revision 大小或合并次数推进。

订阅仅从已应用公开入口投影生成，并继续交集过滤当前授权；新增链路配置还需匹配依赖就绪证据。待切换时保留仍健康的旧入口配置，不向用户提前展示未就绪目标。内部监听、临时探测路径、出站 UUID、出口私钥和内部拓扑都不进入用户订阅。

## 取舍

- 独立内部 UUID 增加少量配置和状态，但允许逐入口隔离、轮换、撤销；复用用户 UUID 或共用出口凭证会破坏边界。
- 双凭据和端点并存提高恢复能力，但离线入口会延长旧秘密有效期；紧急撤销与无中断切换不能同时无条件保证。
- 事务 outbox、精确探测和恢复边界比单个 dirty 时间戳复杂，但它们分别解决跨服务器顺序、真实通路和撤旧后回滚问题，不能互相替代。
- 保持用户账本不变，将复杂度集中在模型、编译及历史授权读取；内部运维统计以后单独设计。

## 未来实现的验收

本阶段只审阅设计，以下链路行为尚未实现或实测；现有单跳 Reality CI 不能作为链式中转验收。

1. 输入排列变化不改变 source hash 或配置字节；拒绝环、多出口、多级链路、端口冲突、已删除/退役依赖；无终端用户的内部监听仍正确编译。
2. 共享出口的不同入口使用不同 UUID，各代不复用用户 UUID；日志、面板列表、outbox、订阅不出现内部秘密；缺少能力的 Agent 明确拒绝链路变更。
3. 出口未应用、仅端口打开、Reality 认证失败或受控目标不可达时，不切换用户路由；两次真实探测均确认使用本代凭证，而非旧出站或直连。
4. 入口离线、探测失败、重复/乱序确认、面板/Agent 重启和通知丢失时保留旧凭证；出口撤旧失败保留双凭证。请求重复可重放，错 generation/revision/hash 不能推进。
5. 在入口应用、固定恢复边界、撤旧各步骤前后注入崩溃，重启后不能自动恢复已被撤销的代；从旧备份恢复需重新核对。版本合并不能越过准备确认屏障。
6. 同固定端口更换 Reality 私钥必须提示维护影响；双监听过渡验证旧新路径都真实可达，全部入口确认后才移除旧监听。
7. 经两台真实服务器上传/下载，用户账本只出现入口记录；内部认证、探测、inbound/outbound 总量不入账；出口独立直接用户仍正常入账。
8. 注入内部及未授权用户 counter 时，Agent outbox 不产生对应记录；直接上传非法批次时面板整批回滚、不 ACK。重启、reload、相同大小的新增流量及重复重放不重复计入或遗漏已观测用量。
9. 旧 source 格式、撤权前末次采样及离线批次仍按历史授权入账；改出口不改变入口用户 UUID、统计名字及历史记录。
10. 改共享出口的 host/port/key/SNI/short ID/兼容版本，事务为所有受影响入口留下待办；worker 重启恢复。原生字节不变时不增 revision，但更新本轮依赖和探测证据；无关出口用户变更不触发全入口发布。
11. 并发编辑与发布不使用混合 generation、不清除更新的 dirty；被引用出口的删除/退役返回依赖冲突，显式切换完成后才能删除；订阅不泄漏内部拓扑。
12. 本机非 Agent 进程在无认证、错误认证或凭证过期时不能使用探测入口；每次探测凭证不同且本机其他用户不可读取，正确认证也不能访问受控目标以外的地址或端口。完成、取消、超时及 Agent 崩溃/重启后不能继续使用遗留探测路径；不能执行这些限制的运行时明确拒绝该探测方法，不把链路标记为就绪。
