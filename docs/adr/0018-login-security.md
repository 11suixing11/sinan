# ADR 0018：单管理员登录限速与 TOTP

- 状态：已采纳，2026-09-30；先记录决策，再实现。
- 范围：单管理员登录和二步验证，不增加管理员角色、权限体系或外部身份服务。

## 算法与依赖

采用 [RFC 6238](https://www.rfc-editor.org/info/rfc6238/) 的 30 秒时间步长，使用 [RFC 4226](https://www.rfc-editor.org/info/rfc4226/) 的 HMAC-SHA1 动态截断得到 6 位数字。每个配置生成独立的 20 字节随机秘密，使用无填充 Base32 和 `otpauth://totp` 手动导入验证器。允许当前时间步以及前后各一个时间步；成功消费的步号持久保存，后续请求只能消费更大的步号。需要主机保持可靠时间同步，时钟回退不会清空已消费状态。

面板直接引用已经存在于 lockfile 的 `hmac 0.12`、`sha1 0.10` 和 `data-encoding 2`，复用成熟的 MAC 和 Base32 实现。SHA1 仅用于兼容验证器的 HMAC 构造，不用作密码哈希或制品摘要。替代方案是新增完整 TOTP 库，但目前所需算法与存储事务边界很小；自行实现 HMAC 或 Base32 会增加不必要的密码编码风险。密码继续使用 Argon2。

## 限速及资源上限

`ConnectInfo<SocketAddr>` 提供 TCP 实际 peer；将 IPv4-mapped 地址规范成 IPv4 后作为限速键，不读取 `X-Forwarded-For` 或 `Forwarded`。每个 peer 的固定 60 秒窗口最多接受 8 次登录或二步验证变更尝试，全局每窗口最多 64 次；通过两级额度检查的认证尝试，无论成功或失败都计数；因额度或并发上限返回 429 的请求不消耗额度，已超额的单个 peer 不能继续耗尽全局预算。PostgreSQL 保存计数，重启不重置窗口；全局行锁串行极短的计数事务，并在锁内清理过期 peer 记录。全局额度限制每窗口能产生的新 peer 行数，避免攻击者导致无界内存或数据库增长。窗口边界允许短时两倍突发，4 个既有并发许可继续限制 Argon2 工作数，许可由实际的阻塞计算任务持有，客户端中断也不会提前释放；额度耗尽返回 HTTP 429。

面板在反向代理后会看到代理地址，该代理后的用户共享额度。默认不信任可伪造的转发头；未来若需按真实客户端细分，必须先定义明确的可信代理列表。当前没有自动放行回环地址或本机 CI。

## 登录与验证码消费

登录一次请求包含密码与可选的 `totp_code`。只有密码正确且已启用 TOTP 时验证码也正确，才创建管理员 session。验证密码后锁定同一管理员行，再读取最新 TOTP 状态并检查验证码；更新最后使用步号和创建 session 在同一事务中提交。错误、缺失、重放的验证码与错误密码统一拒绝，不以密码成功创建中间会话。

TOTP 成功消费后，相同步号不能再用于登录或关闭。并发请求由管理员行锁保证仅一个成功；启用确认也消费对应步号，因此确认后立即用同一码登录会被拒绝，应等待验证器更新。

## 配置生命周期

- 查询状态需要有效会话，只返回启用状态与是否存在尚未过期的待确认设置，不返回秘密。
- 开始设置需要有效会话和管理员密码。生成的新秘密绑定当前 session hash，5 分钟有效，只在这次生成响应返回 Base32 和导入 URI；响应 `Cache-Control: no-store`。重复开始会生成新秘密并替换旧的待确认设置，不再次读取展示旧秘密。
- 确认需要发起设置的会话和有效验证码；在管理员行事务中确认未过期并消费该步号，然后启用。未确认或过期的配置不会参与登录。
- 已启用时不能直接重新开始设置。关闭需要有效会话、密码和当前未使用验证码。
- 启用或关闭成功时，在同一事务中撤销其他管理员 session，保留完成操作的当前会话。事务内重新确认当前会话仍有效，防止已撤销请求恢复设置或绕过撤销。

秘密只保存在 PostgreSQL 的管理员记录中，因为服务器必须能够计算验证码；不会进入普通 API、日志、URL 查询参数或浏览器持久存储。数据库账号、数据卷及备份必须按身份凭证保护；本方案不宣称数据库泄漏后仍能保护 TOTP 秘密。浏览器仅在生成后的当前页面内存显示，离开页面或启用后移除。

## 恢复和验收

不设置密码单独关闭 TOTP 的后门，也不自动发放恢复码。丢失验证器时，需要部署所有者通过受保护的数据库管理通道清空管理员的 TOTP 与 pending 字段，同时删除全部管理员 session，再登录重新设置；执行前先确认主机和数据库的管理权。普通面板密码不能替代这个独立管理权限。恢复操作应记录操作者和时间，不记录秘密。

验收包括 RFC 向量、错误/超窗验证码、并发重放、密码不能单独绕过二步验证、设置过期与会话绑定、确认/关闭的原子性、其他会话撤销、实际 HTTP peer 限速、伪造转发头不能绕过、全局上限与重启计数保留。UI 使用中文，支持手动秘密与导入 URI 复制、确认启用、关闭和登录验证码输入。
