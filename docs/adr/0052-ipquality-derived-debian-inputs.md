# ADR 0052：从认证 Debian 缓存派生最小 IPQuality 输入

日期：2026-10-02。状态：实现与 117 项受影响工具合同验收完成；真实派生磁盘准入拒绝，正向最小制品及 builder 验收待执行。详情见 [验收记录](../acceptance/ipquality-derived-inputs.md)。

## 问题

完整 NodeQuality 的 ARM64 收集已经取得二进制和对应源码闭包，旧收据属于完整工具配置。独立 IPQuality 只需要十一种直接包及其依赖；改写旧 collection 的 kind 会伪造来源，而把全部 237 个包直接绑定并构建不能证明最小 rootfs。重复下载或复制约一 GiB 正文也会浪费专用小磁盘节点的管理空间。新步骤只准备真实最小制品的输入，继续保留原完整执行与发布门禁。

## 选择

新增显式派生入口，要求 root、原生 Debian 12 及匹配架构。输入是完整旧 NodeQuality materials、collection、imports、独立 keyring 审查记录和缓存；旧收据、字节与单链接规则保持。每次重新核对父记录身份、InRelease 签名、索引和全部正文，不以历史 `source_authenticated=true` 代替认证。

派生使用 IPQuality 固定工具配置、空 dpkg 状态、仅 lo 的独立网络命名空间和固定 file 源。APT 只更新派生列表及打印选择；所选包和对应源码必须逐项是父认证库存的精确子集。缺少任何正文就拒绝，不能下载、安装或回退到宿主已有软件。

原 cache 只读借用，输出新元数据和派生证据。缓存根及每个借用文件有目录/普通文件身份、设备、inode、大小与摘要记录；拒绝链接或跨出登记根的路径，创建与清理只作用于新输出。逻辑材料字节和新增输出占用分别记录，不把共享缓存当作零成本，也不全局放松普通文件的单链接限制。后续 prepare 仍重新验证并独立复制选定材料，复制费用由原工厂单独准入。

新 derivation 收据绑定父 kind、父 materials/collection 摘要、固定 profile 与实现摘要、实际求解工具及命令/输出、隔离证据、新库存和缓存关系。它明确表示派生，不伪造一次新的 HTTP 收集。派生 bind 使用独立分支重新验证父、子、缓存与 profile，再把真实 candidate 加入输入锁；已有 collect/bind 行为保持兼容。

## 资源与认证

继续保留至少 512 MiB 磁盘管理空间、inode、内存、总输出预算与绝对截止保护。离线求解的展开预算从重新验证的 Release 获取未压缩 Packages 的 Size/SHA256，并以有界流式解压验证完整字节、大小和摘要；不能用旧阶段采样代替新上限。APT 的列表、镜像、临时副本与元数据费用须分别计入。原求解入口缺少认证展开证据时保持原有保守预留。

动态轮询是资源保护，不是文件系统硬配额。停止后所属进程和挂载须清理确认；失败证据保留，旧缓存不删改。容量拒绝属于真实结果，不降低预留、隐式扩容或清理历史材料来把它改成通过。

## 验收边界

先完成实现、测试代码及文档，再冻结统一验收。覆盖父收据与 imports 不一致、架构错误、缓存变更或缺项、索引解压超限/截断/摘要错误、非精确子集、profile 变更、只读和单链接、资源拒绝、停止及清理、派生 bind 重验证。专用 Debian 上的实际派生单独记录选择数量、材料身份、新空间和 cgroup 状态。

派生及候选绑定都不批准镜像或 builder，不证明已 provision 的真实启动身份，也不审批许可证或创建可复现 rootfs。`builder_approved`、`runtime_image_identity_verified`、`reproducibility_verified`、`full_ready` 保持 false；正式制品、签署、发布、部署与 Agent/sing-box 联合负载另行签收。完整 NodeQuality 的商业工具许可及整体整改剩余条件不缩小。
