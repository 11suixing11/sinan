# ADR 0025：按 IP 与入口保留逐数据库成功快照

- 状态：已确定。
- 对应任务：Issue #23；依赖逐条错误分类 PR #34。

## 决策

保留 `server_ip_quality` 名称、旧 `payload` 和 `checked_at`，主键扩展为 `(server_id, ip, provider)`。入口记录保存最近查询批次时间、最近一个数据库成功时间、所有已知数据库成功快照的共同有效期和按数据库索引的本轮错误。只有所有已知数据库都拥有成功快照时入口 `fresh_until` 才有值，它不代表本轮查询全部成功。

七个 database 是同一 check-place 入口的响应形状。明细表以入口主键加 database 为键，分别保存最新尝试和最后成功快照，以及 `last_attempt_at`、`last_success_at`、`fresh_until`、`last_error`。失败只更新尝试和错误；成功快照、成功时间、有效期保持不变。每个数据库成功后单独更新快照，不要求其余数据库成功。成功时间在响应解析成功时记录，有效期从该成功时间计算；不使用失败时间、读取缓存时间或持久化时间延长有效期。

管理 API 继续返回原结构；status/error/尝试元数据反映最新批次，fields 来自最后成功快照。新增历史标记与成功时间，使当前失败可同时展示历史字段；历史结果不计为当前成功，缺少成功快照仍显示未知。读取在一个 repeatable-read 事务中组装入口和明细，避免刷新期间出现混合代次。

迁移保留旧 payload 原值，只将明确 succeeded 且有字段的数据库迁为成功快照。旧成功时间采用已有逐条尝试时间，缺少时使用旧查询批次 `checked_at`；这是旧数据可提供的时间精度。逐条尝试时间和分类缺失时保持未知，不按错误文字猜测。旧 expires_at 仅关联当时明确成功的数据，不把失败对象的有效期当作成功证明。

换 IP 不删除旧入口记录。页面读取仍只选择设备当前 IP；旧 IP 再出现时可恢复原数据，各 IP、入口和数据库互不覆盖。较早批次的延迟结果不能替换较新尝试。服务器删除后不再写入新结果。

刷新 admission 在同一服务器行锁事务中检查运行租约和最近尝试，再保存租约，避免并发请求分别通过检查。请求正常结束按持有的时间戳清理租约；异常退出后最多等待既有六十秒租约过期，旧请求不能清理后续租约。查询总时限仍为四十秒，网络策略保持不变。

## 替代方案

只给旧 IP payload 合并 fields 会混淆当前状态与历史成功，也难以保持部分成功的独立有效期。直接重命名旧表会扩大路由和历史数据兼容范围。此处保留入口表，并用规范化明细保存两份快照，迁移和事务边界可独立验证。
