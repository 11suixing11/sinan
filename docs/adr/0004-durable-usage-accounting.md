# ADR 0004：单端计量与持久化差值账本

- 状态：已确定，MVP 不得更改。
- 对应任务说明：第 4 节第 4 条。

## 背景

网络断线、消息重发、进程崩溃和运行时计数清零均可能导致流量重复计算或遗失。读取后清零也会在读取与持久化之间制造不可恢复的窗口。

## 决策

只在用户认证的一端计量一次。通过统计 API 累计读取，始终设置 `reset=false`。Agent 在本地计算与同一 `epoch` 基准值的差值，并在同一个 SQLite 事务内更新基准值、分配递增 `seq`、写入待上报队列。

批次携带 `epoch`、`seq` 和时间范围。面板按 `(server_id, epoch, seq)` 去重，以 `(server_id, epoch, seq, stat_name)` 唯一约束保存记录，事务提交成功后确认；重复批次仍返回确认。Agent 收到确认后标记记录，随后清理。未确认批次在重连、重启后继续发送。

Agent 主动重载或重启运行时前读取终值，再开启新 `epoch`。发现累计计数变小也开启新周期，并记录可能存在的缺失窗口。

## 影响

传输采用至少一次投递，依靠面板幂等入库避免重复累计。Agent 重启不应无条件开启新周期；持久账本是恢复依据。不能声称意外运行时重启前尚未采样的字节已被恢复。

## 验证

覆盖差值、事务恢复、周期切换、计数回退、重复批次、重复确认及 Agent 重启后的队列续传。真实验证区分已上报数据不丢失与意外重置可能产生的采样缺口。
