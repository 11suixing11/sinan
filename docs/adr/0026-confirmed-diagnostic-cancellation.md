# ADR 0026：诊断取消由设备确认清理

状态：已实现，独立验收见 [确认式取消](../acceptance/diagnostic-cancellation.md)。关联 Issue #19。

管理员发出取消请求时，面板只能证明请求已经保存，不能证明设备已停止。诊断进程可能仍在下载、排队启动、运行或清理挂载，也可能处于断连或 Agent 重启期间。

选择增加独立的 `diagnostic.cancel.request` / `diagnostic.cancel.result` 协议和 `diagnostic:confirmed-cancel` 能力。任务状态先进入 `cancel_requested`，只有已认证设备确认整个诊断单元的进程与挂载都已清理，才进入 `cancelled`。普通诊断状态回报不能提交取消终态。尚未具备验证能力的后端不宣告该能力，界面禁用取消并明确提示升级。

面板取消请求持久化后才发送 WebSocket 通知。Agent 先把已知任务与服务器身份绑定的取消意图写入 SQLite，再唤醒独立诊断任务；HTTP 待取消列表与持久结果 outbox 恢复断连和重启。WebSocket 接收循环不等待服务停止。重复请求及重复确认保持幂等；服务停止失败、仍有活动进程或挂载、无法读取证据时保留待确认并继续重试。

准备阶段可以中断下载，且启动前再次检查取消意图。已写入持久启动检查点的启动请求必须先结束，再停止和验证，防止在提前确认后创建单元。运行状态与取消请求竞争时，普通终态报告可以保留，但不能结束待确认状态。已经自然完成的任务拒绝新取消请求；已取消任务拒绝迟到的运行状态倒退。

服务操作经过 `ServiceManager`，systemd 命令经过 `Privileged`。单元名称只能由已知诊断 UUID 生成，校对已保存的模块、版本、工作目录与单元身份，协议不接受任意单元名。systemd 清理证据包括状态、主进程和控制进程 PID、整个 cgroup 子树的进程，以及工作目录下的宿主挂载；已加载单元还必须具有私有挂载命名空间和 `KillMode=control-group`。不删除报告目录，便于保存现有报告和后续章节 sidecar。

首版确认后端为 Linux systemd / cgroup v2。OpenRC 与非 Linux 后端缺少同等清理证据，不宣告支持；不能把一次 `stop` 成功作为清理确认。没有增加生产依赖。前端验收用现有浏览器运行时提供的 Playwright，单独列为开发验证工具。
