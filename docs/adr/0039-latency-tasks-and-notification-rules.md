# ADR 0039：统一延迟任务与完整服务器通知

状态：2026-10-01 按用户要求实现；本地验证，未发布或实机签收。

用户要求参考本地 NodeFlare 的「配置延迟检测」与通知，并明确选择完整补齐资源超限、到期、流量和 Telegram 配置功能。覆盖 ADR 0038 对通知仅限离线的阶段范围；继续使用现有管理员权限、站内事件和 Telegram 队列，不引入新依赖，也不改变诊断能力的发布门禁。

## 延迟检测

- 新增统一任务模型及管理员接口 `/api/latency-tasks`。任务定义 TCP/ICMP 目标、间隔、线路、启停状态、服务器集合和新服务器默认分配开关。
- 使用现有 `network_probes` 与 Agent `ProbeSpec` 协议。每个分配具有独立的测量 ID；Agent 的 30 秒配置刷新、四路并发、持久化上传与展示历史直接复用。无需为统一管理升级 Agent 协议。
- 统一任务最多 32 个；每台服务器的独立拨测加统一任务合计最多 32 个。批量分配使用一个事务，任何节点满额均整批回滚；新增服务器连同初始拨测和默认任务一起保存，超限不留下半成品节点。
- 默认分配仅作用于之后新增的服务器；已存在的服务器由显式勾选决定。使用事务锁协调任务修改和新增服务器，修订号避免旧表单覆盖刚分配的新节点。
- 同一测量 ID 的方式、目标和端口不可变；修改名称、间隔及暂停保留历史。取消分配后再分配使用新 ID，删除或取消分配后迟到的旧结果确认并丢弃，不归入新目标。旧历史沿用原七天保留机制。
- 管理员单机列表携带可选任务归属；Agent 和匿名看板仍接收原来的协议形状。统一任务的单机副本不能通过旧接口改写，需回到统一管理页面。

## 通知与告警

- 将原离线事件表重命名为 `server_alert_events`，保留旧 ID、历史与通知队列外键；增加类型、来源键、内容与判定详情。旧设置兼容反序列化，新到期、流量提醒默认关闭，不自动创建资源规则。
- 全局通知开关控制所有事件；原离线全局开关与单服务器开关仍仅作用于离线。离线延迟、首次上报要求及重启宽限保持不变。
- 资源规则最多 20 条，可选择全部或指定服务器；支持处理器、内存、磁盘使用率及选定网卡上下行速率。窗口为 1–1440 分钟，以每个完整分钟最后一条采样的平均值或最小值判断。每分钟都须有有效样本，离线、缺失、无效分母不作为零或恢复；恢复需完整有效窗口。这里的“持续”表示各分钟观测点均超限，不承诺秒级无间断超限。
- 评估每 30 秒进行。按服务器独立事务处理，不锁住整批服务器；指标使用流式读取，只保留最多 1440 个时间点的五项数值，避免累计全部历史 JSON。静态内存/磁盘总量作为旧 Agent 的容量分母；设备扩容后旧窗口的比例可能随最新总量变化。
- 到期提醒每个到期日期一次，可提前 1–365 天；过期七天内仍可补提醒。沿用自动续费的记录顺延，不执行付款。
- 流量提醒从 50–100% 中指定起点，每增加五个百分点产生一次提醒，最高到 100%。使用现有 UTC 账单周期、网卡筛选、方向、额度和矫正后的服务器用量；用整数精确比较阈值，不用浮点数决定是否触发。跨越多条提醒线会分别记录。缺口保留不完整标记，不声称与供应商结算一致。
- 到期日期、流量周期/范围/额度/方向和提醒线组成去重标识，另存有界保留的提醒收据，不因流量矫正后再次越线或关闭再开启而重复提醒；新日期和新周期重新判断。资源告警则按正常→超限→恢复的状态变化通知。规则修改结束旧事件并取消旧待发消息。

## Telegram

- 保持机器人令牌只写不回显、固定官方接口、无代理继承和禁止重定向；加入话题 ID、纯文本模板、预览及手动测试。测试只使用已保存配置，每 30 秒最多一次；不会因为读取设置或保存表单自动发送测试。
- 模板仅替换 `{{title}}`、`{{server}}`、`{{message}}`、`{{time}}`、`{{event}}`，单次替换、不执行表达式、不递归展开节点名称。模板最多 4000 UTF-16 单位，渲染后按 4096 单位限制截断。时间使用 UTC；关闭链接预览。
- 修改机器人、接收会话或话题都会取消旧待发消息；关闭对应通知也会取消。已渲染的待发消息保留原模板，后续新事件使用新模板。
- 沿用持久队列、事件内先告警后恢复、失败退避及 `retry_after`，最多尝试八次。Telegram 不提供此处可用的幂等发送键，远端接受后本地提交失败仍可能重发；事件编号便于辨认。
- 消息请求契约依据 [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage)。本地仅使用回环替身验证，不发送真实机器人消息。

操作与接口示例见 [延迟检测与通知](../monitoring.md)。CI 保持暂停，生产迁移、公网拨测、Telegram 实际送达及多平台节点效果须单独验证。

2026-10-02 的 [ADR0050](0050-authorized-probe-leases.md) 在本历史实现上增加目标来源/同意记录、独立短期许可协议与设备停止保护，覆盖新设备恢复一天离线配置的旧行为。旧八字段协议和历史保持，旧 Agent 尚未升级时的限制仍存在；本 ADR 的历史验证不替代新组合冻结验收。
