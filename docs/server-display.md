# 服务器信息展示页

登录后的默认首页为 `/#/overview`，点击服务器卡片进入 `/#/overview/<服务器 ID>`。后台“服务器”页刷新按钮旁的“服务器展示”和侧栏“展示首页”都可返回总览，展示页右上角“进入后台”可回到既有管理界面。

本轮按用户要求复刻 NodeFlare 的**服务器信息展示界面**：全宽布局、顶部汇总、紧凑卡片、深浅主题，以及硬件/系统信息和资源曲线。后台管理、接入/升级、代理业务、诊断管理和原有登录流程保持现状。展示接口继续要求管理员登录，不新增匿名访问。

## 展示内容

- 总览：在线数量、网卡累计计数、实时上下行、名称/系统/架构/主机名及地区/分组/标签搜索，支持状态、地区和分组筛选。
- 卡片：处理器、内存、磁盘、交换内存、网卡速率和累计计数、运行时间、TCP 连接数与采样状态；按线路显示延迟、ICMP 丢包率或 TCP 连接失败率及近期 20 格色条，卡片最多显示三个目标，其余在详情切换。每格对应一个配置采样间隔，缺采样保持灰色。
- 详情：硬件、系统、设备版本、心跳/采样时间，处理器/内存/磁盘/网络历史曲线，已配置的拨测结果，以及逐网卡、磁盘读写、GPU 信息。
- 资产：卡片呈现手动填写的地区、分组、标签、成本、到期日期及周期流量；详情显示账单周期、统计网卡与观测范围。设置“在展示总览中隐藏”后，不再计入总览卡片和汇总，后台仍可管理。
- 深浅主题只保存在当前浏览器；样式限定在展示页，不覆盖后台。界面使用中文，不增加字体、图标 CDN 或运行时依赖。

服务器状态每 5 秒刷新；历史指标每 15 秒读取增量重叠窗口，每分钟补读所选完整窗口，补齐延迟上传的数据。页面隐藏时暂停轮询。资源曲线提供 15 分钟、1 小时、2 小时，沿用现有接口的两小时与最多 7200 条限制。拨测卡片使用一次认证汇总请求，每 15 秒读取各目标最近 20 条记录；详情配置每 30 秒刷新，结果每 15 秒刷新，可切换目标查看 1/6/24 小时的延迟和丢包双曲线。按目标读取最多 8641 条，覆盖最小 10 秒间隔的一整天；未指定目标的旧接口继续保留 4096 条限制。目标读取使用新增 0015 数据库索引。页面只读取已有任务，不会自动创建公网目标或启动诊断。

鼠标悬停或使用左右方向键可查看曲线读数，首尾键跳至首末采样，点击图例切换显示。缺失值、超长采样间隔保持断线，真实零值保留。曲线按时间桶保留首末值和极值，限制绘制开销。

## 数据语义

在线由面板判定，与指标新鲜度分别显示。离线、过期、无采样时间或读取失败时，不把旧速率加入实时汇总；保留最后信息并提示其状态。没有数据时显示“—”，不会补成零。接口失败不冒充空列表；登录失效仍回到原登录页。

“网卡累计”是各接口最近上报计数的合计，可能因重启重置、包含虚拟接口，不能作为计费总量或代理用户用量。总览累计仅汇总上下行计数完整的设备，缺失设备数量另行注明。卡片第四个资源指标使用实际交换内存。

成本、到期、地区、分组和标签来自后台填写，不根据 IP 推测。“周期流量”使用面板收到的带时间戳网卡计数增量，按 UTC 账单日汇总；首次样本只建立基线，未观测到的历史不补算。显示所选网卡、统计方式和观测缺口，不作为供应商账单凭据；达到额度仅提示，不停止服务。自动顺延到期记录不代表实际续费或扣款。配置方法、单位和周期规则见 [服务器资产与流量额度](server-assets.md)。

## 持续拨测

在后台服务器详情的“持续网络拨测”中添加名称、目标地址、TCP 端口或 ICMP 类型、10–3600 秒间隔及线路备注，例如“电信”“联通”“移动”。展示页按实际备注呈现，不根据地址猜测运营商。未配置时显示配置提示；目标方向是**服务器到指定地址**，不代表浏览器到服务器的延迟。域名使用系统解析返回的首个单播地址；需要固定 IPv4/IPv6 时分别配置相应字面地址。

类型、目标地址和端口创建后固定；改变方向时新建目标，避免将旧历史或离线设备迟到的结果标为新方向。名称、线路备注、间隔和启用状态仍可编辑。接口更改固定字段返回 409，原配置与历史保持。

Agent 每轮执行四次 TCP 连接或 ICMP 回显。延迟取成功响应的平均值，四次都没有响应时延迟为空、失败率为 100%；TCP 连接失败率不等同于 IP 丢包率。Unix 使用系统 ping 汇总中的收发数和平均延迟，重复响应不降低丢包率，BSD 未逐行打印的迟到响应也按工具汇总计入。Windows 使用 PowerShell 调用 .NET Ping 并输出结构化 JSON，避免本地化文本及编码影响。

工具缺失、权限不足、DNS 失败、输出不完整/被截断或执行超时属于“检测不可用”，曲线保留空缺。兼容旧协议时 `loss_percent` 的数字占位字段保持不变，**只要 `error` 非空值（包括空字符串），该条延迟和失败率都不能作为实测值使用**；新的展示页与后台都遵循此规则。暂停、离线、读取失败和超过 `max(60 秒, 3 × 配置间隔)` 的旧样本不作为当前读数。

完整 Unix ping 汇总仍不能掩盖 stderr 工具诊断；发送权限失败也可能被工具计为已发送，因此这类结果记为不可用。命令保留发送错误输出，真实无响应且无工具诊断时仍可记录 100% 丢包。

Unix 需要系统 `env` 和 `ping`，macOS IPv6 使用 `ping6`；精简 Debian/Ubuntu 镜像可由管理员安装 `iputils-ping`，Alpine 可使用带完整 ping 功能的 BusyBox。Windows 需要系统 Windows PowerShell 与 .NET Ping。Agent 不静默安装软件或提高权限，检测不可用时可在后台查看实际错误。

最多配置 32 个目标，同时运行不超过 4 个，单次 DNS 最多 2 秒、命令最多 8 秒、整轮最多 12 秒。过期轮次跳过，不补跑积压轮次；慢目标不会阻塞其他结果落盘和上传，暂停或修改配置会取消已有测量。配置每 30 秒同步，离线最多沿用 24 小时；结果持久化后每 3 秒尝试上传，确认后删除，离线缓存最多 2 小时/4096 条。缓存清理与采样时间使用相同的面板时钟偏移，避免时差导致新数据立即被删。

平台参数依据 [iputils ping](https://www.man7.org/linux/man-pages/man8/ping.8.html)、[BusyBox ping](https://busybox.net/downloads/BusyBox.html#ping)、[FreeBSD ping](https://man.freebsd.org/cgi/man.cgi?query=ping&sektion=8)、[Apple ping6 实现](https://github.com/apple-oss-distributions/network_cmds/blob/main/ping6.tproj/ping6.c) 和 [Microsoft Ping.Send](https://learn.microsoft.com/en-us/dotnet/api/system.net.networkinformation.ping.send?view=netframework-4.8.1)。macOS IPv6 使用 `-X` 总时限，避免误用 IPv4 的 `-t`/`-W`。

## 来源与验证

参考本地 NodeFlare 工作树 `42eff9e07e12d6ec83e003238c1072cc5afdd39e` 的展示组件和样式，适配 Sinan 既有接口与权限。保留 [NodeFlare MIT 许可](../web/public/notices/NodeFlare.txt)，随 `web/dist` 内嵌发布，页脚可查看来源与许可。

本地验证入口：

```sh
cd web
bun run build
bun test tests
```

`web/tests/server-display.mjs` 使用提交的真实构建产物、本机静态服务及拦截 API 夹具，检查三种宽度、两种主题、数据状态、曲线交互、搜索、后台返回和权限错误；通过 `SINAN_PLAYWRIGHT_MODULE`、`SINAN_CHROME_PATH` 指定本机浏览器工具，可用 `SINAN_UI_SCREENSHOT_DIR` 保存截图。夹具测试不代表生产 Agent 或公网实机验收。CI 按当前安排保持暂停。

`web/tests/server-assets.mjs` 另检查桌面/手机的资产新增、编辑、失败重试、清空、精确字节保存、地区/分组筛选、标签搜索和展示隐藏。

拨测回归包含解析夹具、真实 TCP 监听/拒绝、慢任务并发及取消、SQLite 重启/部分确认/时钟偏移、PostgreSQL 权限和逐目标完整历史。以下条件测试需在安装好系统工具、允许回环 ICMP 的测试机上单独执行：

```sh
cargo test -p sinan-agent-core icmp_measures_real_ipv4_and_ipv6_loopback -- --ignored --nocapture
```

本轮仅在本机 Linux 实测 IPv4/IPv6 回环，不代表 macOS、FreeBSD、Windows、公网丢包或长期驻留已经验收；这些平台的参数与结果解析由本地夹具覆盖，仍需各平台专用测试机验证。
